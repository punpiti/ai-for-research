Workshop

ตรวจ PDF ก่อนส่ง: ตรวจเนื้อหาแยกจากหน้ากระดาษ แก้หนึ่งรอบ และบันทึกความพร้อมส่ง

ใน workshop นี้คุณจะตรวจ PDF ของต้นฉบับ PM2.5 จำลองทั้งด้านเนื้อหาและหน้ากระดาษเทียบกับข้อกำหนด Journal A แก้ที่ต้นทางหนึ่งรอบแล้ว build ใหม่ และกรอก submission/submission-readiness.md ให้ทุกแถวมีสถานะพร้อมหลักฐาน

ก่อนเริ่ม (ต้องมีอยู่แล้ว)

  • จากหัวข้อ “ต้นฉบับ Markdown ชุดเดียว → LaTeX → PDF” (workshop หลัก):
    • module-08-work/build/manuscript.pdf และ log ใน module-08-work/build/
    • module-08-work/generated/main.tex
    • ถ้ายังไม่มีสองข้อนี้ ให้ทำหัวข้อนั้นก่อน
  • ไฟล์ที่ตัวติดตั้ง Module 1 สร้างไว้ (คัดลอกมาจาก course-materials/module-08/):
    • module-08-work/source/manuscript.md — ต้นฉบับที่คุณแก้มาจากหัวข้อก่อนหน้า
    • module-08-work/input/analysis-summary.csv และ module-08-work/input/module-07-highlights.md — ใช้ตรวจตัวเลข
    • module-08-work/journal-dossiers/journal-a/original/profile.md — ข้อกำหนด Journal A (1,800 คำไม่รวม references, abstract ≤ 180 คำ ไม่มีหัวข้อย่อย, ตาราง ≤ 3, รูป ≤ 3, author–year, ฉบับ review ไม่มีชื่อผู้แต่ง/สังกัด/acknowledgments)
    • module-08-work/submission/submission-readiness.md — แม่แบบที่มีตาราง Gate ว่างอยู่ (ยังไม่กรอก)
  • ถ้าไม่พบไฟล์ของหัวข้อนี้ใน module-08-work/ ให้สั่ง AI รัน AIRR init module-8 ครั้งเดียว (ไฟล์ที่คุณแก้แล้วจะไม่ถูกเขียนทับ)

คำที่ใช้ใน workshop นี้

  • content QA — ตรวจข้ออ้าง ตัวเลข citation และข้อจำกัดกับไฟล์หลักฐาน
  • visual QA — ตรวจหน้ากระดาษ ตัวอักษร รูป ตาราง และการล้น
  • PASS / FAIL / BLOCKED — ผ่าน, ไม่ผ่าน, หรือยังตัดสินไม่ได้เพราะขาดหลักฐาน/การตัดสิน
  • next action — การแก้ถัดไปพร้อมผู้รับผิดชอบและตำแหน่งไฟล์

ขั้นตอน

  1. ตรวจเนื้อหาด้วยตัวเอง (4 นาที) เปิด build/manuscript.pdf คู่กับ input/analysis-summary.csv แล้วจดสิ่งที่พบ

    • ปัญหา วัตถุประสงค์ วิธี ผล และข้อสรุปสอดคล้องกัน
    • ตัวเลขในข้อความ ตาราง และรูปตรงกับ input/ (เช่น 37.02 → 34.36 และ South 29.22 → 34.56 µg/m³)
    • ไม่มีผล citation หรือขั้นตอนวิธีที่ไม่มีในต้นฉบับ
    • ชื่อเรื่อง abstract และ conclusion ไม่อ้างเกินผล ไม่มีถ้อยคำเชิงเหตุและผล และระบุข้อจำกัดชัด
    • ฉบับ blinded ไม่มีชื่อผู้แต่ง สังกัด หรือ acknowledgments

    ตรวจ: บันทึกปัญหาเป็นสองกลุ่ม “เนื้อหา” กับ “หน้ากระดาษ” พร้อมหน้า/หัวข้อ

  2. ให้ AI ช่วยตรวจหน้ากระดาษและข้อกำหนด ส่ง prompt นี้ AI จะตอบเป็นรายการ PASS/FAIL (ยังไม่แก้ไฟล์)

    ตรวจ module-08-work/build/manuscript.pdf และ log ใน module-08-work/build/ เทียบกับข้อกำหนดใน module-08-work/journal-dossiers/journal-a/original/profile.md แยกข้อความจาก PDF เพื่อตรวจเนื้อหาขาดหาย ตรวจว่าตัวเลขใน PDF ตรงกับ module-08-work/input/analysis-summary.csv ตรวจหน้ากระดาษ: ข้อความหรือรูปล้นคอลัมน์ ตารางอ่านได้ หัวข้อค้างท้ายหน้า citation หรือ reference ที่ขึ้นเป็น ? รูปอ่านได้เมื่อพิมพ์ขาวดำ จำนวนคำ จำนวนรูปและตาราง จัดทำรายการ PASS/FAIL พร้อมตำแหน่ง (หน้า/หัวข้อ) และวิธีแก้ที่ไฟล์ต้นทาง ห้ามแก้ไฟล์ใด แล้วหยุดรอ

    ตรวจ: AI รายงานตำแหน่งและวิธีแก้โดยยังไม่แก้ไฟล์

  3. ตรวจรายการของ AI เปิดตำแหน่งที่ AI ระบุใน PDF จริงอย่างน้อย 2 จุด และดูว่ามีข้อที่คุณพบในขั้น 1 แต่ AI ไม่พบหรือไม่ แยกรายการที่ได้เป็นสองกลุ่ม “เนื้อหา” กับ “หน้ากระดาษ”

    ตรวจ: เปิดดูอย่างน้อยสองตำแหน่งจริงและบันทึกข้อที่ AI พลาด

  4. แก้หนึ่งรอบ (4 นาที) เลือกปัญหาที่สำคัญที่สุด แก้ที่ source/manuscript.md (หรือ literature/references.bib / figures/) (ถ้าจะทำขั้น 6: ก่อนสร้างใหม่ คัดลอก generated/main.tex เก็บไว้เป็นฉบับก่อนแก้) ให้ AI สร้าง generated/main.tex ใหม่ แล้ว build ใหม่ด้วยคำสั่ง build เดิม เปิด build/manuscript.pdf ฉบับใหม่ ยืนยันว่าแก้แล้วและไม่มีจุดอื่นเปลี่ยนความหมาย

    ตรวจ: ปัญหาที่เลือกหายไป และจุดอื่นไม่เปลี่ยนความหมาย

  5. บันทึกความพร้อมส่ง ส่ง prompt นี้ AI จะกรอกตารางใน submission/submission-readiness.md จากนั้นตรวจและแก้ด้วยตัวเอง

    กรอก module-08-work/submission/submission-readiness.md ตามตาราง Gate ที่มีอยู่ ใส่สถานะ PASS / FAIL / BLOCKED หลักฐาน และ next action ของทุกแถว ใช้เฉพาะผลตรวจที่เราทำในรอบนี้และข้อกำหนดใน profile ห้ามปิด BLOCKED เอง ห้ามรับรองการตอบรับตีพิมพ์ ข้อที่ต้องเป็นการตัดสินของมนุษย์ (เช่น declarations, AI-use disclosure, ethics/data statement) ให้ระบุใน Human decision required

    ชุดฝึกนี้ยังไม่มี title page แยก cover letter declarations ฯลฯ ตาม Submission Package ของ Journal A — แถวที่เกี่ยวข้องต้องไม่เป็น PASS

    ตรวจ: ทุกแถวมีสถานะ หลักฐาน และ next action; รายการที่ต้องให้คนตัดสินยังเป็น BLOCKED

  6. (ถ้ามีเวลา) ตรวจการแก้ไขด้วย latexdiff ส่ง prompt นี้ AI จะใช้ generated/main.tex ฉบับก่อนแก้ (ที่คุณเก็บไว้ในขั้น 4) กับฉบับปัจจุบันสร้าง diff.tex

    เก็บ snapshot ของ generated/main.tex ฉบับก่อนแก้และฉบับปัจจุบัน ใช้ latexdiff สร้าง diff.tex และ compile สำเนานั้น ตรวจทุกจุดที่เปลี่ยนข้อกล่าวอ้าง ตัวเลข citation หรือข้อจำกัด รายงานการเปลี่ยนที่ตั้งใจและผิดคาด ห้ามแก้ diff.tex แล้วนำกลับไปแทน source หลัก

    ถ้าไม่ได้เก็บ main.tex ฉบับก่อนแก้ไว้ในขั้น 4 ให้ข้ามขั้นนี้

    ตรวจ: diff แยกจาก source หลักและทุกการเปลี่ยนข้ออ้าง/ตัวเลขได้รับการตรวจ

Exploring

ตรวจ PDF ก่อนส่ง: ตรวจเนื้อหาแยกจากหน้ากระดาษ แก้หนึ่งรอบ และบันทึกความพร้อมส่ง

ในโจทย์นี้คุณจะเขียน prompt เอง (ไม่มี prompt สำเร็จรูปให้) เพื่อตรวจ PDF ของเอกสารตัวเองแยกด้านเนื้อหาและหน้ากระดาษ แก้ที่ต้นทางหนึ่งรอบ แล้วเขียนรายงานความพร้อมส่ง

ก่อนเริ่ม (ต้องมีอยู่แล้ว)

  • ทำ workshop หลักของหัวข้อนี้แล้ว (รู้ขั้นตรวจเนื้อหา/หน้ากระดาษ และตาราง Gate ใน module-08-work/submission/submission-readiness.md)
  • PDF ของเอกสารตัวเองที่ build จากต้นฉบับได้แล้ว พร้อมไฟล์ต้นฉบับนั้น — จาก exploring workshop ของหัวข้อ “ต้นฉบับ Markdown ชุดเดียว → LaTeX → PDF” หรือบทความ/รายงานที่คุณกำลังจะส่ง
  • ไฟล์ข้อมูล/ผลต้นทางที่ตัวเลขในเอกสารมาจาก (ของคุณเอง)
  • ข้อกำหนดผู้แต่งของแหล่งเผยแพร่เป้าหมาย จากเว็บของแหล่งเผยแพร่นั้น

โจทย์

  1. เก็บสำเนา PDF ฉบับก่อนแก้ไว้ และเริ่มไฟล์ output/prompts.md ไว้บันทึก prompt ทุกรอบ
  2. ตรวจเนื้อหาและหน้ากระดาษแยกกัน บันทึกผลเป็น output/qa-content.md และ output/qa-layout.md ที่คุณสร้างในขั้นนี้
  3. แก้ที่ไฟล์ต้นทางอย่างน้อยหนึ่งรอบ แล้ว build PDF ฉบับหลังแก้
  4. เขียน output/submission-readiness.md (PASS / FAIL / BLOCKED + หลักฐาน + ตำแหน่ง + ผู้รับผิดชอบ)

ข้อกำหนด

  • output/prompts.md เก็บ prompt ทุกรอบ (prompt, สรุปผลที่ได้, สิ่งที่ปรับในรอบถัดไปและเหตุผล)
  • ระบุว่าตรวจผลของ AI อย่างไร (เทียบกับไฟล์/เอกสารต้นทางใด) และแก้อะไรเอง
  • ผลงาน: output/qa-content.md, output/qa-layout.md, output/submission-readiness.md และ PDF ก่อน/หลังแก้
  • ตัวเลขทุกตัวในบทคัดย่อและผลหลักต้องตรวจกับไฟล์ต้นทางด้วยตัวเอง ไม่ใช่เชื่อรายงานของ AI
