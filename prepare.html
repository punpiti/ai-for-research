รู้จัก Terminal / CLI

Terminal คืออะไร?

Terminal คือช่องสำหรับบอกคอมพิวเตอร์ให้ทำงานด้วยข้อความ ส่วน CLI หรือ Command-Line Interface คือโปรแกรมที่เราเรียกใช้ผ่านช่องนี้ หนึ่งบรรทัดคือหนึ่งคำสั่ง ในกิจกรรมนี้ไม่ต้องจำคำสั่งและไม่ต้องพิมพ์เอง—อ่านก่อน กด Copy วาง แล้วกด Enter

ขั้นที่ 2 · Installation

ติดตั้งซอฟต์แวร์

ติดตั้งครั้งแรกด้วยคำสั่งเดียวที่ดาวน์โหลด Script แล้วรันต่อทันที: เตรียม VS Code พร้อม AI extension ที่เลือก, ตัวแสดง usage ของ AI บน status bar, PDF Viewer, Rainbow CSV และ JSON Crack, Python 3.12, LaTeX/XeLaTeX ผ่าน TinyTeX, Pandoc, Poppler สำหรับถอด text layer จาก PDF และ OCR ไทย–อังกฤษ เครื่องมือที่ต้องใช้สิทธิ์ระบบจะติดตั้งให้จบในรอบนี้ ส่วนตัวอ่าน PPTX/XLSX และไลบรารีเฉพาะกิจกรรมให้ AI ติดตั้งเฉพาะส่วนที่ต้องใช้ใน course environment โดยไม่ถามซ้ำเมื่อเริ่มใช้งาน; DOCX อ่านผ่าน Pandoc ที่เตรียมไว้แล้ว

ติดตั้งต่อเนื่อง: Script ติดตั้งสิ่งที่ขาดตาม AI ที่เลือก โดยไม่ถามยืนยันทีละโปรแกรม เมื่อจบแล้วจึง Sign in หรือใส่ API key ไม่ต้องเลือกรุ่น Python, แพ็กเกจ LaTeX หรือ AI ตัวอื่นระหว่างติดตั้ง
สิทธิ์ครั้งแรก: Windows จะถาม UAC เฉพาะเมื่อขาดเครื่องมือระบบ; macOS และ Linux อาจถามรหัสผ่านเพื่อติดตั้งเครื่องมือระบบ จากนั้น Python, TinyTeX และแพ็กเกจเพิ่มเติมใช้พื้นที่ของบัญชีผู้ใช้ปกติ

เลือก extension จากผู้พัฒนา official หรือที่มียอดติดตั้งสูง: PDF Viewer เปิด PDF, Rainbow CSV แยกสีและจัดแนวคอลัมน์ CSV และ JSON Crack ซึ่งเป็น extension official ของโครงการ JSON Crack แสดง JSON เป็นแผนภาพ ทั้งสามตัวติดตั้งพร้อมกันทุกตัวเลือก AI ส่วนการอ่าน จัดรูปแบบ และพับโครงสร้าง JSON มีอยู่ใน VS Code ของ Microsoft แล้ว

เปิด PDF หรือ CSV ได้จากรายการไฟล์ สำหรับ CSV ใช้ Rainbow CSV: Virtual Align CSV Columns เพื่อจัดแนวโดยไม่เปลี่ยนข้อมูล สำหรับ JSON เปิดไฟล์แล้วคลิกไอคอน JSON Crack ที่มุมขวาบนของ editor ยอดติดตั้งที่ตรวจเมื่อ 7 ตุลาคม 2026: PDF Viewer ประมาณ 2.8 ล้านครั้ง, Rainbow CSV ประมาณ 24.3 ล้านครั้ง และ JSON Crack ประมาณ 7.8 แสนครั้ง ตัวเลขนี้เป็นยอดติดตั้งสะสม ไม่ใช่จำนวนผู้ใช้ปัจจุบัน

ตัวแสดง usage เลือกตาม AI: Claude ใช้ growthjack.claude-code-usage, Codex ใช้ ganymede404.vscode-codex-usage และ OpenRouter ใช้ ThiagoSantosDevBR.openrouter-ai-monitor โดยแสดง quota, เครดิต หรือเวลาที่จะ reset บริเวณ status bar ด้านล่าง ตัว OpenRouter ต้องสั่ง OpenRouter: Set API Key หนึ่งครั้งหลังเปิด VS Code; key เก็บใน Secret Storage ของ VS Code ไม่บันทึกเป็น plain text ใน settings

ถ้ารันซ้ำหรือแก้ปัญหา: คัดลอกคำสั่งติดตั้งด้านล่างใหม่แล้วรันได้เลย แล้วตรวจว่าเห็น SETUP_VERSION 2026.10.07.19

Windows 11

เปิด PowerShell ปกติ

1 คัดลอกคำสั่งนี้แล้วกด Enter ครั้งเดียว

& { $setup = Join-Path $env:TEMP 'ai-research-setup.ps1'; Invoke-WebRequest -UseBasicParsing -ErrorAction Stop "https://urban.cpe.ku.ac.th/ai-for-research/downloads/setup-windows.ps1" -OutFile $setup; powershell -NoProfile -ExecutionPolicy Bypass -File "$setup" -Mode Install -Agent codex }

เริ่มใน PowerShell ปกติเพียงหน้าต่างเดียว หากเครื่องมือระบบยังไม่ครบ Script จะเปิดหน้าต่าง Admin หนึ่งครั้ง ให้ตอบ Yes ที่ UAC แล้วรอให้กลับมาทำงานต่อในหน้าต่างเดิม เมื่อเครื่องมือระบบครบแล้วจะข้าม Admin เมื่อเตรียม Python และ PDF ผ่าน จะเห็น RUNTIME_READY

macOS

เปิด Terminal ปกติ

1 คัดลอกคำสั่งนี้แล้วกด Enter ครั้งเดียว

setup="$(mktemp)" && curl -fsSL "https://urban.cpe.ku.ac.th/ai-for-research/downloads/setup-macos.sh" -o "$setup" && AI_GRAD_AGENT=codex bash "$setup" --install

ใช้ Terminal ปกติหน้าต่างเดียว ติดตั้ง Homebrew เมื่อยังไม่มีและใส่รหัสผ่านเมื่อระบบขอ จากนั้นเตรียมเครื่องมือของผู้ใช้ต่อเนื่อง เมื่อเตรียม Python และ PDF ผ่าน จะเห็น RUNTIME_READY Script จะเปิด Workspace ใน VS Code ให้อัตโนมัติ

Linux (Ubuntu/Debian)

เปิด Terminal ปกติ

1 คัดลอกคำสั่งนี้แล้วกด Enter ครั้งเดียว

setup="$(mktemp)" && curl -fsSL "https://urban.cpe.ku.ac.th/ai-for-research/downloads/setup-linux.sh" -o "$setup" && AI_GRAD_AGENT=codex bash "$setup" --install

รองรับ Ubuntu/Debian; ใช้ Terminal ปกติหน้าต่างเดียว Script เรียก sudo หนึ่งช่วงเฉพาะเมื่อขาดเครื่องมือระบบ แล้วเตรียม Python และ TinyTeX ในบัญชีผู้ใช้ปกติ ต้องเห็น RUNTIME_READY

ติดตั้งสำเร็จเมื่อ: เห็น RUNTIME_READY ซึ่งยืนยัน Python ใน venv, XeLaTeX และการสร้าง PDF ภาษาไทยผ่าน template จริง เครื่องมือระบบจะตรวจ Pandoc, pdftotext, pdftoppm, pdfinfo และ OCR ไทย–อังกฤษก่อนเปิด Workspace พร้อม AI panel หากขั้นใดล้มเหลว Script จะหยุดและแสดงข้อผิดพลาด

ระหว่างติดตั้งจะแสดงเฉพาะขั้นหลัก เมื่อเสร็จจะแสดงสรุปเครื่องมือที่ใช้ต่อจากของเดิม รายการที่เพิ่ม และตำแหน่ง log รายละเอียดและประวัติการเปลี่ยนแปลงจะเก็บในเครื่อง หากติดตั้งไม่สำเร็จ Script จะแสดงขั้นที่มีปัญหาและตำแหน่ง log สำหรับตรวจสอบ

มีอยู่แล้วให้ใช้ต่อ

Installer ใช้ซอฟต์แวร์ที่มีอยู่และติดตั้งเฉพาะตัวที่ขาด จะไม่อัปเดตทุกโปรแกรมเป็นรุ่นล่าสุด หาก Node รุ่นเดิมต่ำกว่าที่ AI frontend ต้องใช้ จะเตรียม Node LTS ที่รองรับในพื้นที่เครื่องมือของคอร์สโดยเก็บรุ่นระบบไว้ ส่วน Python 3.12 และ TinyTeX ของคอร์สจะใช้ชุดเดิมเมื่อรันซ้ำ

LaTeX ที่ติดตั้งไว้ระดับระบบอาจยังต้องขอ Admin เมื่อลงแพ็กเกจเพิ่ม จึงเตรียม TinyTeX ที่ผู้ใช้เขียนได้แยกไว้ตั้งแต่ครั้งแรก ผู้เรียนสามารถอัปเดตเครื่องมือภายหลังเมื่อพบปัญหาหรือมีเหตุผลด้านการรองรับงาน โดยบันทึกรุ่นก่อนและหลัง

ถอนชุดทดลองบน Windows จาก installation trace

เปิด PowerShell แบบปกติแล้วรันคำสั่งด้านล่าง Script จะเลือก trace ของการติดตั้งล่าสุดและถามยืนยันก่อนถอน โดยถอนเฉพาะ package, extension, runtime และไฟล์ที่ trace ยืนยันว่าเพิ่มสำเร็จในรอบนั้น แม้การติดตั้งทั้งรอบจะหยุดกลางทาง สิ่งที่มีอยู่ก่อนจะไม่ถูกแตะ และไฟล์ที่แก้หลังติดตั้งจะถูกเก็บไว้

& { $setup = Join-Path $env:TEMP 'ai-research-setup.ps1'; Invoke-WebRequest -UseBasicParsing -ErrorAction Stop "https://urban.cpe.ku.ac.th/ai-for-research/downloads/setup-windows.ps1" -OutFile $setup; powershell -NoProfile -ExecutionPolicy Bypass -File "$setup" -Mode Uninstall }

หากมีหลาย trace ให้ใช้ path ที่ installer แสดงหลังคำว่า Trace: แล้วเพิ่ม -InstallTraceFile "path\to\exact-trace.jsonl" เพื่อเลือก receipt ที่ต้องการโดยตรง Workspace หลักจะไม่ถูกลบทั้งโฟลเดอร์

VS Code และ OpenRouter อยู่ในชุดแรก

Windows และ macOS ติดตั้ง VS Code ให้เมื่อยังไม่มี; Linux ติดตั้งแพ็กเกจ VS Code จาก Microsoft บน Windows โปรแกรมและคำสั่งทั้งหมดทำงานใน Windows โดยตรง

หากเลือก OpenRouter จะติดตั้ง Cline extension ให้ จากนั้นเปิด Cline Settings เลือก OpenRouter ใส่ API key ในช่องที่กำหนด เลือกโมเดล และตรวจเครดิต/ราคา Installer เตรียม extension ให้ แต่การใช้โมเดลขึ้นกับบัญชี OpenRouter ของคุณ

อ้างอิง: Cline กับ OpenRouter

เพิ่มเติม: สำหรับผู้ที่มี WSL2 อยู่แล้ว

WSL2 เป็นทางเลือกสำหรับผู้ที่คุ้นกับ Linux และมี Ubuntu/WSL2 พร้อมใช้งานอยู่แล้ว ใช้ Script ของ Linux ภายใน WSL ได้ โดย Script จะเรียก powershell.exe ของ Windows เพื่อติดตั้ง VS Code และ WSL extension ฝั่ง Windows แล้วกลับมาทำงานใน Ubuntu ไม่ต้องติดตั้ง PowerShell 7 เพิ่ม

Python, LaTeX และคำสั่งวิเคราะห์จะรันใน WSL ให้ตรวจมุมล่างซ้ายของ VS Code ว่าเป็น WSL: Ubuntu หรือชื่อ distribution ของคุณ ดู คู่มือ VS Code ใน WSL

ให้ AI ติดตั้งเพิ่มได้เมื่อจำเป็น

Installer สร้างโฟลเดอร์งาน ai-for-research-workspace ในโฟลเดอร์ผู้ใช้บนเครื่อง และใช้ uv จัดการ Python 3.12 กับ venv ของคอร์ส ส่วน environment, cache และ TinyTeX อยู่ในโฟลเดอร์เครื่องมือแยกจากโฟลเดอร์งาน ไฟล์ tools/runtime-env.json บอกตำแหน่งจริง และ tools/runtime-env.sh / tools/runtime-env.ps1 ใช้เปิด environment ซ้ำได้

Workspace มีโครง Agent Project Kit เฉพาะส่วนที่ช่วยลดค่าใช้ AI ได้แก่ AGENTS.md, state สั้น, token budget, startup contract และ token discipline เท่านั้น ค่าเริ่มต้นคือ Standard + Economy: AI อ่านเฉพาะไฟล์ที่เกี่ยวข้อง ใช้ Markdown ที่ถอดไว้ซ้ำ สรุปสถานะเพื่อไม่เล่าบริบทใหม่ และถามก่อน scan/research/test loop ที่มีต้นทุนสูง โดยไม่ตัดการตรวจหลักฐานหรือ test ที่จำเป็น

Codex: Installer สร้าง .codex/config.toml เฉพาะ Workspace นี้ ให้เขียนไฟล์งานและโฟลเดอร์เครื่องมือ ดาวน์โหลดผ่านเครือข่าย และรันคำสั่งโดยไม่ถามยืนยันซ้ำ ยอมรับความเชื่อถือของ Workspace ครั้งแรก แล้วเริ่ม session ใหม่เพื่อโหลดค่า เครื่ององค์กรอาจมีนโยบายที่ override ค่าเหล่านี้ได้

Claude Code: เตรียมการอนุญาตเครื่องมือ Python, Pandoc, XeLaTeX, bibliography, latexmk และ latexdiff เฉพาะ Workspace ผ่าน .claude/settings.local.json คำสั่งอื่นอาจยังถาม หากมี config เดิม Installer จะเก็บไว้และแจ้งให้ตรวจค่า

Cline/OpenRouter: โหลด environment ของ Workspace ใน Terminal แล้วตั้ง Auto Approve ครั้งแรกใน Cline ให้ตรงกับงาน หากต้องการให้ติดตั้งแพ็กเกจโดยไม่ถาม ต้องเปิดการรันคำสั่งที่ต้องขออนุญาตด้วย เพราะ Cline อาจจัดคำสั่งติดตั้งเป็นกลุ่มนี้ การตั้งค่านี้อนุญาตคำสั่งอื่นด้วย จึงต้องใช้กับ Workspace ที่ไว้วางใจ อ่าน คำอธิบาย Auto Approve ก่อนเลือก

อ้างอิง: Python ผ่าน uv · TinyTeX และ tlmgr · สิทธิ์และเครือข่ายของ Codex

ตรวจว่า Workspace เปิดแล้ว

คำสั่งติดตั้งจะเปิด Workspace ให้อัตโนมัติ หากเห็นโฟลเดอร์งานใน VS Code แล้ว ไม่ต้องเปิดซ้ำ ให้ไปที่ “เชื่อมต่อบัญชี AI” ได้เลย วิธีด้านล่างใช้เมื่อปิดหน้าต่างไปแล้วหรือต้องการเปิดใหม่เท่านั้น

Workspace ไม่เปิดอัตโนมัติ? ดูวิธีเปิดใหม่

Windows 11

เปิดด้วย PowerShell

  1. 1
    เปิด PowerShell แบบปกติ
  2. 2
    คัดลอกคำสั่งด้านล่างแล้วกด Enter
  3. 3
    รอให้ VS Code เปิดโฟลเดอร์งาน
code --profile "AI for Research - codex" "$HOME\ai-for-research-workspace"

macOS

หาก Workspace ยังไม่เปิด

  1. 1
    เปิด VS Code
  2. 2
    กด Command (⌘) + O
  3. 3
    กด Command (⌘) + Shift + G
  4. 4
    วางตำแหน่งโฟลเดอร์ด้านล่าง กด Enter แล้วกด Open
~/ai-for-research-workspace

Linux (Ubuntu/Debian)

เปิดด้วย Terminal

  1. 1
    เปิด Terminal
  2. 2
    คัดลอกคำสั่งด้านล่างแล้วกด Enter
  3. 3
    รอให้ VS Code เปิดโฟลเดอร์ผ่าน Linux
code --profile "AI for Research - codex" "$HOME/ai-for-research-workspace"

ฝึกบอกบริบทของคุณให้ AI

กิจกรรมนี้ฝึกให้ AI รู้ว่าใครกำลังทำงานอะไรและต้องการความช่วยเหลือแบบใด โดยให้ข้อมูลเท่าที่จำเป็น ช่องที่ไม่เกี่ยวข้องข้ามได้ และไม่ต้องระบุรหัสนิสิต เบอร์โทร อีเมล ที่อยู่ credential หรือข้อมูลส่วนบุคคลของผู้อื่น

  1. 01
    คัดลอก Prompt สัมภาษณ์
    แก้ตัวเลือกใน {{…}} ก่อนส่ง หากยังไม่ทราบให้คงคำว่า “ถามฉัน” ไว้

    ✎ แก้ก่อนส่ง: เปลี่ยนข้อความใน {{…}} ให้ตรงกับคุณ หรือปล่อยให้ AI ถามทีละข้อ

    ช่วยสัมภาษณ์ฉันเพื่อสร้าง Learner Profile สำหรับใช้ใน AI for Research โดยถามครั้งละหนึ่งคำถามและรอคำตอบ ห้ามสร้างหรือแก้ไขไฟล์จนกว่าฉันจะตรวจ profile และอนุมัติ ข้อมูลที่ฉันต้องการให้ถามหรือยืนยัน: 1. ชื่อภาษาไทย: {{ถามฉัน — ข้ามได้}} 2. ชื่อภาษาอังกฤษ: {{ถามฉัน — ข้ามได้}} 3. สังกัด/หน่วยงาน: {{ถามฉัน — ระบุเท่าที่จำเป็น}} 4. บทบาทหรือระดับการศึกษา: {{เช่น นิสิตปริญญาโท อาจารย์ นักวิจัย หรือบุคคลทั่วไป}} 5. สาขาหรือความเชี่ยวชาญ: {{ถามฉัน}} 6. ชื่ออาจารย์ที่ปรึกษา: {{ถามฉันถ้ามีและฉันยินยอมให้ระบุ มิฉะนั้นบันทึกว่าไม่ระบุ}} 7. หัวข้อวิจัยหรือประเด็นที่สนใจ: {{ถามฉัน}} 8. ระยะของงานตอนนี้: {{เริ่มหาโจทย์ / ทำ proposal / เก็บข้อมูล / วิเคราะห์ / เขียนเผยแพร่ / อื่น ๆ}} 9. ผลงานที่อยากได้จากการเรียน: {{ถามฉัน}} 10. ภาษาที่ต้องการใช้ทำงาน: {{ไทย / อังกฤษ / สองภาษา}} 11. ข้อจำกัดด้านเวลา เครื่องมือ หรือการเข้าถึงข้อมูล: {{ถามฉัน}} 12. ระดับความอ่อนไหวของข้อมูล: {{public / internal / confidential / sensitive / ยังไม่แน่ใจ}} 13. วารสาร การประชุม หรือแหล่งเผยแพร่ที่สนใจ: {{ถามฉัน — หากยังไม่มีให้บันทึกว่า ยังไม่ทราบ}} 14. กลุ่มผู้อ่านหรือผู้ใช้ผลที่ต้องการสื่อสารด้วย: {{ถามฉัน}} ก่อนถาม เตือนฉันว่าไม่ต้องให้รหัสนิสิต เบอร์โทร อีเมล ที่อยู่ รหัสผ่าน หรือข้อมูลส่วนบุคคลที่ไม่จำเป็น เมื่อถามครบให้แสดงข้อมูลผู้เรียนฉบับร่าง แยก “ข้อมูลที่ฉันยืนยัน” “ยังไม่ทราบ” และ “ไม่ประสงค์ระบุ” แล้วถามว่าต้องแก้อะไรก่อนบันทึก ห้ามเดาหรือเติมข้อมูลแทนฉัน เมื่อฉันพิมพ์ว่า “อนุมัติและบันทึก” เท่านั้น ให้สร้างโฟลเดอร์ profile/ และไฟล์ต่อไปนี้: 1. profile/learner-profile.yaml — ข้อมูลที่ฉันยืนยันในรูปแบบที่โมดูลอื่นอ่านได้ 2. profile/learner-profile.md — ฉบับภาษาไทยที่ฉันอ่านและแก้ไขได้ 3. profile/learning-context.md — วิเคราะห์เฉพาะสิ่งที่ช่วยปรับบทเรียน ได้แก่ ระดับคำอธิบาย ตัวอย่างที่เกี่ยวข้อง ภาษา ข้อจำกัด ข้อมูลที่ห้ามส่งออก ค่าเริ่มต้นที่ใช้ได้ และค่าที่ยังต้องถาม ห้ามวิเคราะห์บุคลิกหรือเดาความสามารถ 4. profile/author-profile.bib — สร้างเฉพาะเมื่อฉันต้องการ โดยใช้เพียงชื่อ สังกัด ORCID หรือข้อมูลสำหรับเผยแพร่ที่ฉันยืนยัน ห้ามใช้ BibTeX แทน learner-profile.yaml ก่อนจบ แสดงรายการข้อมูลที่ถูกบันทึก ข้อมูลที่ไม่ได้บันทึก และวิธีแก้ไขไฟล์ในภายหลัง โมดูลถัดไปต้องอ่าน profile/ ก่อนทำงาน หากข้อมูลที่จำเป็นยังไม่ทราบให้ถามฉันทีละข้อและบันทึกหลังฉันอนุมัติ
  2. 02
    ตอบทีละคำถาม
    วาง Prompt ใน Codex panel แล้วตอบเฉพาะข้อมูลที่เกี่ยวข้อง คุณสามารถพิมพ์ “ข้าม” หรือ “ไม่ประสงค์ระบุ” ได้ทุกข้อ
  3. 03
    ตรวจข้อมูลก่อนอนุมัติ
    ตรวจการสะกดชื่อ สังกัด บทบาท หัวข้อ เป้าหมาย และระดับความอ่อนไหว แก้สิ่งที่ AI เข้าใจผิด โดย AI ต้องยังไม่สร้างหรือแก้ไขไฟล์
  4. 04
    อนุมัติแล้วจึงบันทึก
    เมื่อข้อมูลถูกต้อง ให้พิมพ์ “อนุมัติและบันทึก” แล้วตรวจว่าเกิด profile/learner-profile.yaml, profile/learner-profile.md และ profile/learning-context.md
  5. 05
    ตรวจสิ่งที่ AI วิเคราะห์
    เปิด profile/learning-context.md และลบหรือแก้ข้อความที่เดาเกินข้อมูล ไฟล์นี้ควรบอกเพียงว่าจะปรับภาษา ตัวอย่าง การค้น และค่าเริ่มต้นอย่างไร
  6. 06
    สร้างข้อมูลผู้แต่งเมื่อจำเป็น
    หากต้องใช้ในงานเผยแพร่ จึงให้ AI สร้าง profile/author-profile.bib จากข้อมูลที่ยืนยันแล้ว ไฟล์นี้เป็นข้อมูลผู้แต่ง ไม่ใช่ข้อมูลผู้เรียนหลัก
กิจกรรมผ่านเมื่อ: AI ถามทีละข้อ ไม่เดาข้อมูล รอการอนุมัติก่อนสร้างไฟล์ ผู้เรียนเปิดและตรวจข้อมูลทั้งสามไฟล์ได้ และทราบว่าโมดูลถัดไปจะอ่านข้อมูลเหล่านี้เป็นบริบทเพิ่มเติม ส่วน BibTeX เป็นเพียงไฟล์ข้อมูลผู้แต่งที่เลือกสร้างเมื่อจำเป็น

ทดลองไฟล์ Markdown แรก

  1. 01

    คลิก content.md แล้วแก้ข้อความตัวอย่าง
  2. 02
    ดู Markdown Preview
    กด Ctrl+Shift+V (macOS: Command+Shift+V) เพื่อดูผลลัพธ์ที่จัดรูปแบบแล้ว
  3. 03
    ให้ AI อ่านและสร้าง PDF
    วาง prompt ด้านล่างใน Codex panel; agent จะอ่านคำสั่งใน Workspace และใช้ Integrated Terminal เบื้องหลังเมื่อจำเป็น
    อ่าน content.md แล้วสร้าง output/content.pdf ตามรูปแบบที่กำหนดไว้ใน Workspace โดยไม่เปลี่ยนไฟล์ต้นฉบับ จากนั้นตรวจว่าไฟล์ PDF สร้างสำเร็จ
  4. 04
    ตรวจสิทธิ์ของ Workspace
    Codex ที่โหลด config ของคอร์สแล้วจะรันได้ทันที หากยังถาม ให้ยอมรับ Workspace และเริ่ม session ใหม่ สำหรับ Claude ให้ตรวจว่าโหลดการอนุญาต pandoc จาก config ของ Workspace แล้ว
  5. 05
    เปิด PDF
    คลิก output/content.pdf และตรวจว่าเปิดอ่านได้ เป็นกระดาษ A4 ภาษาไทยใช้ Sarabun จาก Google Fonts ที่ติดตั้งพร้อม Workspace และมีรูปแบบสีตาม template
