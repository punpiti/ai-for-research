บันทึกมุมมองเดิม แล้วให้ AI วินิจฉัย problem statement พร้อมตำแหน่ง

ชุดสำรองต้นทางในโครงการ: downloads/module-04-mock/mock-paper-th.pdf (ตัวติดตั้ง M01 ดึงไปที่ module-04-work/thai-mock/input/original/ ผ่าน airr materials module-4 --thai) -->

ใน workshop นี้คุณจะเขียนมุมมองเดิมของคุณต่อ problem statement ลง author-prior.md ก่อน แล้วให้ AI วินิจฉัยบทนำพร้อมตำแหน่ง จนได้ตาราง problem-statement-diagnosis.md ที่ทุกแถวตรวจย้อนได้

เวลา: ประมาณ 15 นาที (ลองทำ 1 ของ Module 3)

ก่อนเริ่ม (ต้องมีอยู่แล้ว)

  • ผ่าน Module 1: เปิด ai-for-research-workspace ใน VS Code และ AI panel เชื่อมแล้ว — โฟลเดอร์ module-03-work/input/original/ ตัวติดตั้งสร้างไว้ให้แล้ว (ว่าง)
  • บทความหรือร่างบทนำของคุณเอง 1 เรื่องที่อ่านเข้าใจและมีสิทธิ์ใช้กับ AI ห้ามนำ manuscript ที่ยังไม่เผยแพร่ ข้อมูลส่วนบุคคล หรือข้อมูลของผู้ร่วมวิจัยเข้า AI โดยไม่ได้ตรวจสิทธิ์ ถ้ามีผู้ร่วมเขียน ใช้เฉพาะไฟล์ที่มีสิทธิ์นำมาใช้กับ AI
  • ชุดสำรองถ้าไม่มีเอกสารของตนเอง: บทความจำลองภาษาไทย mock-paper-th.pdf (บทความจำลอง ไม่ใช่ผลงานตีพิมพ์จริง) ตัวติดตั้ง Module 1 วางไว้ที่ module-04-work/thai-mock/input/original/mock-paper-th.pdf ถ้าตอนติดตั้งเห็น PRACTICE_FILES_READY ถ้ายังไม่มี ให้ดาวน์โหลดจากหน้า Module 4 บทความนี้เขียนขึ้นเพื่อฝึกและตั้งใจใส่ปัญหาไว้ บทนำมีเพียงสองย่อหน้า จึงอาจพบว่าหลายองค์ประกอบไม่มีในเอกสาร ซึ่งเป็นผลวินิจฉัยที่ใช้ได้

ขั้นตอน

  1. วางต้นฉบับ — คัดลอกไฟล์ของคุณ (หรือ mock-paper-th.pdf) ไปไว้ใน module-03-work/input/original/ ห้ามแก้ไฟล์ในโฟลเดอร์นี้หลังวาง

  2. แปลงต้นฉบับเป็น Markdown (ข้ามได้ถ้ามี module-03-work/input/markdown/seed-paper.md อยู่แล้ว) สั่ง AI

    ใช้ไฟล์ที่ฉันวางไว้ใน module-03-work/input/original/ ถ้ามีหลายเรื่องให้ถามฉันเลือกหนึ่ง แปลงเป็น module-03-work/input/markdown/seed-paper.md โดยเก็บหน้า (page marker) และหัวข้อไว้ ห้ามแก้ไฟล์ต้นฉบับ แปลงเสร็จแล้วบอกตำแหน่งไฟล์และหยุด

    เปิด seed-paper.md ที่ AI เพิ่งสร้าง เทียบกับ PDF คร่าว ๆ ว่าหัวข้อ Introduction และ page marker อยู่ครบ

  3. บันทึกมุมมองของคุณก่อนเห็นผล AI (คุณทำเอง) — สร้างไฟล์ module-03-work/output/author-prior.md แล้วเขียนเองสั้น ๆ ว่าคุณคิดว่า problem statement นี้มี

    • จุดแข็งอะไร
    • จุดอ่อนอะไร
    • ข้อสงสัยอะไร

    ใช้เจ็ดองค์ประกอบเป็นรายการตรวจในใจ: ผู้ได้รับผล สภาวะปัญหา หลักฐาน ผลกระทบ ขอบเขต สภาพที่ต้องการ สิ่งที่ยังไม่ทราบ และดูว่ามีภาษาที่ผูกกับวิธีแก้หรือไม่

    ทำขั้นนี้ก่อนให้ AI วิจารณ์ เพื่อจะรู้ได้ว่าอะไรเป็นมุมมองใหม่จริง และไม่คล้อยตามผล AI ภายหลัง ไฟล์นี้คุณเขียนเท่านั้น ถ้าต้องการให้ AI ช่วยถาม ใช้ prompt นี้ (ไม่บังคับ):

    ให้ฉันเขียน module-03-work/output/author-prior.md เองก่อนเห็นผลประเมิน โดยถามทีละข้อถึงจุดแข็ง จุดอ่อน ข้อจำกัด ประเด็นที่คิดว่าครบแล้ว และข้อสงสัย ห้าม AI เติมคำตอบแทน และห้ามแสดงผลวินิจฉัยก่อนฉันเขียนเสร็จ

  4. ให้ AI วินิจฉัยพร้อมตำแหน่ง สั่ง AI

    อ่าน Introduction ใน module-03-work/input/markdown/seed-paper.md เป็นหลัก แยก core statement, ผู้ได้รับผล, สภาวะปัญหา, หลักฐาน, ผลกระทบ, ขอบเขต, สภาพที่ต้องการ, สิ่งที่ยังไม่ทราบ และภาษาที่ผูกกับวิธีแก้ ระบุ heading, paragraph และ page marker ของทุกรายการ จากนั้นชี้ข้อความที่ไม่ชัด ข้ออ้างที่เกินหลักฐาน และความไม่สอดคล้อง แยกสิ่งที่บทความระบุออกจากข้อเสนอของคุณ ห้ามเขียนข้อความใหม่แทนฉัน ถ้า Markdown แยกหัวข้อผิดให้ตรวจ PDF ต้นฉบับ แสดงเป็นตารางแล้วหยุดรอ

    AI จะแสดงตารางวินิจฉัยในแชต ถ้าแถวใดไม่มีตำแหน่ง หรือ AI เขียนบทนำใหม่ให้ ให้สั่งทำใหม่ตามกติกาใน prompt

  5. บันทึกตารางวินิจฉัย สั่ง AI

    บันทึกตารางวินิจฉัยนี้ลง module-03-work/output/problem-statement-diagnosis.md ตามที่แสดง ห้ามเพิ่มหรือแก้เนื้อหา แล้วหยุด

    AI จะสร้าง module-03-work/output/problem-statement-diagnosis.md

  6. เทียบกับมุมมองเดิมของคุณ (คุณทำเอง) — วาง author-prior.md คู่กับ problem-statement-diagnosis.md แล้วจดว่า

    • ข้อใดที่คุณเห็นอยู่แล้ว
    • ข้อใดเป็นมุมมองใหม่จาก AI (ยังไม่ต้องเชื่อ — จะตรวจกับต้นฉบับในหัวข้อถัดไป)
    • ข้อใดที่คุณเห็นแต่ AI ไม่เห็น

ตรวจก่อนจบ

ส่งงาน

  • หัวข้อนี้เป็นส่วนหนึ่งของทางสั้น Module 3 ส่งรวมเมื่อทำครบสี่ไฟล์ (author-prior.md, problem-statement-diagnosis.md จากหัวข้อนี้ และ revision-table.md, citation-for-m4.md ที่จะสร้างในหัวข้อ ตรวจคำวิจารณ์ของ AI แล้วแก้พร้อมเหตุผล) ให้ AI รันเครื่องมือ AIRR check → ยืนยัน → submit ตามหน้า Module 3

Exploring

บันทึกมุมมองเดิม แล้วให้ AI วินิจฉัย problem statement พร้อมตำแหน่ง

ในโจทย์เปิดนี้คุณจะบันทึกมุมมองเดิมของคุณก่อน แล้วเขียน prompt เองให้ AI วินิจฉัย problem statement จากงานอีกชิ้นของคุณตามเจ็ดองค์ประกอบพร้อมตำแหน่ง

ไม่มี prompt สำเร็จรูปให้

ก่อนเริ่ม (ต้องมีอยู่แล้ว)

  • ทำ workshop problem-statement-diagnosis-with-locations แล้ว
  • ข้อความระบุปัญหาจากงานของคุณเองอีกหนึ่งชิ้นที่ไม่ใช่ชิ้นที่ใช้ใน workshop เช่น บทนำของ proposal ที่กำลังเขียน บทนำของบทความที่ตีพิมพ์แล้ว หรือบทนำวิทยานิพนธ์ของนิสิตในที่ปรึกษาที่ได้รับอนุญาตให้ใช้กับ AI
  • ใช้เฉพาะเอกสารที่มีสิทธิ์นำเข้า AI

โจทย์

  1. สร้าง module-03-work/output/prompts.md เอง แล้วบันทึก prompt ที่ใช้ทุกรอบลงไฟล์นี้
  2. เขียนมุมมองเดิมของคุณลง author-prior.md ไฟล์ใหม่สำหรับเอกสารชิ้นนี้ (อย่าเขียนทับไฟล์ของ workshop) ให้เสร็จก่อนรัน prompt วินิจฉัยครั้งแรก และบันทึกเวลาหรือลำดับไว้
  3. เขียน prompt เองให้ AI วินิจฉัยตามเจ็ดองค์ประกอบ และชี้ภาษาที่ผูกกับวิธีแก้
  4. ปรับ prompt ให้เหมาะกับลักษณะเอกสารในสาขาคุณ เช่น บทนำที่ไม่มีหัวข้อแยก เอกสารหลายภาษา หรือ proposal ที่มีหัวข้อ “ความสำคัญและที่มาของปัญหา”

ข้อกำหนด

  • prompt ต้องบังคับให้ทุกรายการมีตำแหน่งที่ตรวจย้อนได้ และห้าม AI เขียนข้อความใหม่แทน
  • ระบุว่าตรวจผลของ AI อย่างไร (สุ่มเปิดต้นฉบับตามตำแหน่งที่อ้างอย่างน้อย 3 รายการ) และแก้อะไรเอง
