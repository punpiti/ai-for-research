เวลาโดยประมาณ (ผู้สอนเห็นเท่านั้น): ≈ 100 นาที (สไลด์ 15 · workshop 40 · exploring 45)

  • ให้ AI แกะรายการอ้างอิงทั้งหมดของเอกสาร แล้วสร้าง refs.bib ที่ทุก entry มีผลจับคู่จาก OpenAlex (identity_check, openalex_id, retracted) และ abstract ที่ประกอบจาก OpenAlex เท่านั้น ช่องที่หาไม่พบระบุตามจริง และสุ่มตรวจ metadata เองกับ DOI หรือหน้าทางการ
  • สร้างคลังฉบับเต็ม (PDF + Markdown พร้อม page marker) เฉพาะ open access ที่เข้าถึงได้อย่างถูกต้อง บันทึกสำนักพิมพ์ที่บล็อกไว้ใน policy และทำรายการ manual-download.md สำหรับฉบับที่ต้องดาวน์โหลดเองผ่านสิทธิ์มหาวิทยาลัย โดยไม่ให้ AI ดาวน์โหลดผ่านสิทธิ์สมาชิกแบบอัตโนมัติ
  • ให้ AI จับคู่ in-text citation ทุกจุดกับรายการอ้างอิงและสร้างทะเบียนการอ้างอิงหนึ่งแถวต่อหนึ่งรายการ แล้วผู้เรียนอ่านฉบับเต็มของรายการเสี่ยงเองด้วยสี่คำถาม ตัดสินสถานะและการตัดสินใจ (เก็บ ลดขอบเขต ตัดออก หาแหล่งแทน) จากหลักฐาน ระบุระดับที่ตรวจ (abstract หรือ full_text) และสรุปปัญหาคุณภาพของชุดอ้างอิงทั้งชุด

Workshop 1

สร้าง BibTeX พร้อม abstract และผลจับคู่จาก OpenAlex

ใน workshop นี้คุณจะให้ AI แปลงบทความจำลองเป็นข้อความ แกะรายการอ้างอิง และจับคู่กับ OpenAlex จนได้ refs.bib ครบทุกรายการ แล้วสุ่มตรวจเอง 3 รายการ

บทความจำลองเป็นเอกสารสมมติเพื่อฝึก ห้ามนำไปอ้างอิง ขั้นนี้ตรวจเฉพาะชั้น "ref มีจริง" ยังไม่ต้องตัดสินว่ารายการใดปลอม refs.bib ที่ได้ใช้ต่อในกิจกรรม open-access-fulltext-library และ citation-register-audit

ก่อนเริ่ม (ต้องมีอยู่แล้ว)

  • ผ่าน Module 1: เปิด ai-for-research-workspace ใน VS Code และ AI panel เชื่อมแล้ว
  • ไฟล์ที่ตัวติดตั้ง Module 1 วางไว้ให้ (เมื่อหน้าต่างติดตั้งแสดง PRACTICE_FILES_READY):
    • module-04-work/input/original/mock-paper.pdf — บทความจำลอง
    • course-materials/module-04/citation-audit-rules.md — กติกาการตรวจ (อ่านอย่างเดียว)
    • course-materials/module-04/citation-register-template.csv — แม่แบบทะเบียน (อ่านอย่างเดียว)
  • ถ้ายังไม่มีไฟล์เหล่านี้: ใช้ Prompt "เตรียมไฟล์" บนหน้า Module 4 (AI จะรันเครื่องมือ AIRR materials module-4 ให้) หรือดาวน์โหลดจากหน้า Module 4 แล้ววางตามตำแหน่งข้างต้นเอง
  • OpenAlex API key ของคุณเก็บในตัวแปร OPENALEX_KEY ของเครื่องแล้ว (ถ้ายังไม่มี ทำขั้น "OpenAlex API key" ด้านล่างก่อน) ห้ามวาง key ลงใน Prompt ไฟล์งาน หรือภาพหน้าจอ

คำที่ใช้ใน workshop นี้

  • ref มีจริง — ชั้นแรกของการตรวจ: เอกสารมีอยู่จริง และ author, year, title, venue, DOI ตรงกับแหล่งทางการ
  • OpenAlex — ฐานข้อมูลเปิดของผลงานวิชาการ ใช้จับคู่รายการอ้างอิงและดึง abstract
  • refs.bib — ไฟล์ BibTeX หนึ่ง entry ต่อหนึ่งรายการอ้างอิง พร้อม field ผลการจับคู่
  • page marker — เครื่องหมายเลขหน้าใน paper.md ที่ทำให้อ้างกลับไปหน้าเดิมของ PDF ได้
  • not_found — ค้นใน OpenAlex แล้วไม่พบ ยังไม่ได้แปลว่าปลอม

OpenAlex API key — ทำครั้งเดียว (ถ้ามีแล้ว ข้ามได้)

workshop นี้ให้ AI เรียก OpenAlex ซึ่งต้องใช้ API key ของแต่ละคน (ฟรี) ถ้าไม่มี key ทุกเครื่องในเครือข่ายเดียวกันจะแบ่งโควตาฟรีรายวันชุดเดียวกัน และหมดก่อนทำเสร็จ ถ้าเคยตั้ง OPENALEX_KEY แล้ว (เช่น ใน Module 2) ข้ามไปขั้นถัดไปได้เลย

  1. เปิด openalex.org/settings/api สมัครหรือเข้าสู่ระบบ แล้วคัดลอก API key
  2. เก็บ key ในตัวแปร OPENALEX_KEY ด้วยตัวเอง (ห้ามวาง key ในแชต AI หรือในไฟล์ใด ๆ)
    • Windows: เปิด PowerShell พิมพ์ setx OPENALEX_KEY "key ของคุณ"
    • macOS / Linux: เพิ่มบรรทัด export OPENALEX_KEY="key ของคุณ" ใน ~/.zshrc หรือ ~/.bashrc
  3. ปิด VS Code แล้วเปิดใหม่ แล้ววาง prompt นี้
ตรวจว่ามีตัวแปร OPENALEX_KEY หรือไม่ ตอบแค่ว่ามีหรือไม่มี ห้ามแสดงค่า

ตรวจ: AI ตอบว่ามี OPENALEX_KEY และไม่มี key ปรากฏในแชตหรือไฟล์ใด

ขั้นที่ 1 — ให้ AI แกะรายการอ้างอิงและจับคู่กับ OpenAlex

วาง Prompt นี้ใน AI — AI จะสร้าง module-04-work/input/markdown/paper.md และ module-04-work/output/refs.bib

อ่าน course-materials/module-04/citation-audit-rules.md ก่อน แล้วแปลงงานวิจัยใน module-04-work/input/original/ เป็น module-04-work/input/markdown/paper.md พร้อม page marker แล้วแกะรายการอ้างอิง ท้ายเรื่องทั้งหมดตามลำดับ ห้ามเดาชื่อเรื่อง ผู้แต่ง หรือ DOI ที่อ่านไม่ชัด จากนั้นค้นแต่ละรายการใน OpenAlex API ด้วย DOI ก่อน ถ้าไม่มี DOI ให้ค้นด้วยชื่อเรื่องและปี แล้วสร้าง module-04-work/output/refs.bib หนึ่ง entry ต่อหนึ่งรายการ ใส่ abstract ที่ประกอบจาก OpenAlex เท่านั้น พร้อม field abstract_source, openalex_id, identity_check, retracted และ local_fulltext (เว้นว่างไว้ก่อน) ถ้าไม่พบหรือ metadata ไม่ตรง ให้บันทึกตามจริง ห้ามแต่ง abstract ใช้ API key จากตัวแปร OPENALEX_KEY เท่านั้น และห้ามพิมพ์ key ลงไฟล์ log หรือผลลัพธ์ใด สรุปจำนวน matched, metadata_conflict, not_found, abstract not found และ retracted แล้วหยุดรอ

ตรวจ: เปิด paper.md แล้วเห็น page marker และ AI ตอบกลับเป็นจำนวนครบห้ากลุ่ม (matched, metadata_conflict, not_found, abstract not found, retracted) — จดตัวเลขไว้

ขั้นที่ 2 — เปิด refs.bib และดู field ของทุก entry

เปิด module-04-work/output/refs.bib ดูว่าทุก entry มีช่อง abstract_source, openalex_id, identity_check, retracted, local_fulltext และรายการที่ไม่มี abstract เขียนว่า abstract not found ไม่ใช่ข้อความที่ AI สรุปขึ้นเอง

ในบทความจำลองจะมีบางรายการ metadata ไม่ตรง บางรายการไม่พบ บางรายการไม่มี abstract และอย่างน้อยหนึ่งรายการถูกถอน

ตรวจ: จำนวน entry ที่ขึ้นต้นด้วย @ ใน refs.bib เท่ากับจำนวนรายการในหัวข้อ References ท้ายบทความ และไม่มี entry ใดเขียนว่ารายการนั้นปลอม

ขั้นที่ 3 — สุ่มตรวจเอง 3 รายการ

เลือก 3 entry เปิด DOI หรือหน้าทางการในเบราว์เซอร์ เทียบ author, year, title และ venue ทีละช่องกับ refs.bib ถ้า OpenAlex ขัดกับหน้าทางการ ให้ยึดหน้าทางการและบันทึกความต่างไว้

ตรวจ: คุณมีผลเทียบทีละช่องของ 3 รายการ และสำหรับรายการที่ระบบบอกว่า matched หน้าที่ DOI เปิดไปแสดงชื่อเรื่องเดียวกับใน refs.bib

ขั้นที่ 4 — ตรวจว่าไม่มีความลับหลุด

ค้นใน refs.bib, paper.md และไฟล์ log ที่ AI สร้าง (ถ้ามี) ว่าไม่มีค่า key ปรากฏ ใน VS Code ใช้ Search (Ctrl+Shift+F · macOS: Cmd+Shift+F) ค้นด้วยตัวอักษรช่วงต้นของ key

ตรวจ: ผลค้นหาไม่พบค่า key ในไฟล์ใดของ module-04-work/

Exploring 1

สร้าง BibTeX พร้อม abstract และผลจับคู่จาก OpenAlex

ในโจทย์นี้คุณจะเขียน prompt เองให้ AI จับคู่รายการอ้างอิงของงานคุณกับ OpenAlex จนได้ refs.bib ของงานนั้น พร้อมบันทึกการสุ่มตรวจและ prompt log

ไม่มี prompt สำเร็จรูปให้ ใช้ Prompt ของบทความจำลองเป็นโครงได้ แต่ต้องเขียนใหม่ให้เข้ากับงานของคุณ

ก่อนเริ่ม (ต้องมีอยู่แล้ว)

  • ทำ workshop bibtex-with-openalex-abstracts กับบทความจำลองแล้ว
  • course-materials/module-04/citation-audit-rules.md (ตัวติดตั้ง Module 1 วางไว้ให้ อ่านอย่างเดียว)
  • OpenAlex API key ในตัวแปร OPENALEX_KEY ของเครื่อง (ตั้งไว้ก่อนเรียน Module 4)
  • บทหรือส่วนที่อ้างอิงมากของงานคุณหรือของนิสิตที่ดูแล (เฉพาะงานที่ได้รับอนุญาต และตัดข้อมูลส่วนบุคคลออกแล้ว)

โจทย์

  1. สร้างโฟลเดอร์ module-04-work/<ชื่องาน>/input/original/ แล้ววางเอกสารของคุณลงไป
  2. สร้างไฟล์ module-04-work/<ชื่องาน>/output/prompts.md สำหรับเก็บ prompt ที่ใช้ทุกรอบ
  3. เขียน prompt ให้ AI แปลงเอกสาร แกะรายการอ้างอิงทั้งหมด จับคู่กับ OpenAlex และสร้าง module-04-work/<ชื่องาน>/output/refs.bib ที่มีช่องสำหรับการตรวจครบ แล้วหยุดรอให้คุณตรวจ
  4. ถ้างานมีรายการภาษาไทย ให้ prompt ระบุแหล่งที่ค้นต่อเมื่อไม่พบใน OpenAlex (ดูหัวข้อ ตรวจรายการอ้างอิงภาษาไทย: ไม่พบใน OpenAlex ไม่ได้แปลว่าปลอม)
  5. สุ่มตรวจด้วยตนเองอย่างน้อย 3 รายการกับ DOI หรือหน้าทางการ และบันทึกผลเทียบทีละช่อง

ข้อกำหนด

  • prompt ต้องระบุ: ลำดับการจับคู่ (DOI ก่อน แล้วจึงชื่อเรื่องและปี) กติกาเมื่อไม่พบ (บันทึกตามจริง ห้ามแต่ง abstract หรือ DOI) การใช้ key จากตัวแปรของเครื่องเท่านั้น และจุดหยุดรอ
  • ระบุว่าแก้อะไรใน refs.bib เอง และเพราะอะไร

Workshop 2

คลังฉบับเต็มในเครื่อง: ดาวน์โหลดเท่าที่ถูกต้อง และรายการดาวน์โหลดเอง

ใน workshop นี้คุณจะให้ AI ดาวน์โหลดฉบับเต็มที่เป็น open access ของรายการใน refs.bib เข้าคลัง literature/ แปลงเป็น Markdown และทำรายการที่ต้องดาวน์โหลดเอง

ก่อนเริ่ม (ต้องมีอยู่แล้ว)

  • module-04-work/output/refs.bib — สร้างในกิจกรรม bibtex-with-openalex-abstracts จากบทความจำลอง module-04-work/input/original/mock-paper.pdf
  • โฟลเดอร์ literature/pdf/ และ literature/markdown/ (ตัวติดตั้ง Module 1 สร้างไว้ให้) — คลังนี้อยู่ที่เดียวใน workspace ใช้ร่วมทุกงานและทุกโมดูล ไม่ต้องสร้างแยกต่อชิ้นงาน
  • ทบทวนกติกาจากสไลด์ 10 ของ Module 4: AI โหลดเฉพาะ open access; ฉบับที่ต้องใช้สิทธิ์มหาวิทยาลัยคุณโหลดเองผ่าน VPN

คำที่ใช้ใน workshop นี้

  • open access — ฉบับเต็มที่สำนักพิมพ์หรือคลังเปิดให้อ่านได้โดยไม่ต้องใช้สิทธิ์สมาชิก
  • คลัง literature/ — ที่เก็บ PDF (literature/pdf/) และ Markdown (literature/markdown/) ของฉบับเต็ม ใช้ส่วนตัว ห้ามเผยแพร่หรือแชร์ต่อ
  • <citation_key> — key ของ entry ใน refs.bib ใช้เป็นชื่อไฟล์ในคลัง
  • page marker — เครื่องหมายเลขหน้าในไฟล์ Markdown ใช้อ้างหน้าของฉบับเต็ม
  • publisher-download-policy.md — บันทึกโดเมนสำนักพิมพ์ที่บล็อกการดาวน์โหลด เพื่อไม่ให้ AI ลองซ้ำ

OpenAlex API key — ทำครั้งเดียว (ถ้ามีแล้ว ข้ามได้)

ขั้นที่ 1 — ให้ AI โหลด open access และทำรายการดาวน์โหลดเอง

จาก module-04-work/output/refs.bib ให้อ่าน literature/publisher-download-policy.md (สร้างใหม่ถ้ายังไม่มี) แล้วดาวน์โหลดเฉพาะฉบับ open access ตาม OpenAlex ไปที่ literature/pdf/{citation_key}.pdf ข้ามรายการที่มีไฟล์อยู่แล้ว และข้ามสำนักพิมพ์ที่ policy ระบุว่าบล็อก ถ้าพบการบล็อกใหม่ (403, captcha หรือหน้า login) ให้บันทึกโดเมนลง policy แล้วไม่ลองซ้ำ แปลงไฟล์ที่ได้เป็น literature/markdown/{citation_key}.md พร้อม page marker และใส่ path ลง field local_fulltext ใน refs.bib รายการที่เหลือให้เขียนลง module-04-work/output/manual-download.md เป็นรายการติ๊กได้ พร้อมชื่อเรื่อง DOI สำนักพิมพ์ เหตุผล และชื่อไฟล์ที่ต้องบันทึก ห้ามดาวน์โหลดผ่านสิทธิ์สมาชิกแบบอัตโนมัติ และห้ามใช้แหล่งที่ไม่ถูกต้องตามลิขสิทธิ์ สรุปจำนวนฉบับเต็มที่ได้ ที่ต้องเปิดจากหน้าวารสาร และที่ต้องใช้สิทธิ์มหาวิทยาลัย แล้วหยุดรอ

ตรวจ: ทุก PDF ใน literature/pdf/ มีไฟล์ Markdown ชื่อเดียวกันใน literature/markdown/ และใน refs.bib รายการที่ได้ฉบับเต็มมี local_fulltext ชี้ไฟล์ที่เปิดได้จริง

ขั้นที่ 2 — ตรวจไฟล์ที่แปลงแล้วหนึ่งไฟล์

เปิด literature/markdown/<citation_key>.md หนึ่งไฟล์คู่กับ PDF ของมันใน literature/pdf/ ดูว่าข้อความ ตาราง และ page marker ตรงกัน ถ้าไม่ตรง ให้จดไว้ เพราะกิจกรรม citation-register-audit จะอ้างหน้าจาก page marker นี้

เปิด module-04-work/output/manual-download.md ดูว่าทุกรายการที่ยังไม่มีฉบับเต็มมีชื่อเรื่อง DOI สำนักพิมพ์ เหตุผล และชื่อไฟล์ที่ต้องบันทึกครบ แล้วเปิด literature/publisher-download-policy.md ดูว่ามีโดเมนที่บล็อกถูกบันทึกไว้หรือไม่

ตรวจ: ทุกรายการใน manual-download.md ขึ้นต้นด้วย - [ ] และมีห้าช่องครบ จำนวนรายการรวมกับจำนวน entry ที่มี local_fulltext แล้วเท่ากับจำนวน entry ทั้งหมดใน refs.bib และโดเมนที่บล็อก (ถ้ามี) ปรากฏใน policy ครั้งเดียว

ขั้นที่ 4 — โหลดฉบับที่ต้องใช้สิทธิ์มหาวิทยาลัยด้วยตนเอง

ทำกิจกรรม citation-register-audit ต่อได้เลยด้วยฉบับเต็มที่มีอยู่ ยังไม่ต้องโหลดผ่านสิทธิ์มหาวิทยาลัย เมื่อพร้อม: เชื่อม VPN ของมหาวิทยาลัย เปิดรายการใน manual-download.md ผ่านเบราว์เซอร์ บันทึกตามชื่อไฟล์ที่ระบุลง literature/pdf/ ติ๊กรายการที่ได้แล้ว จากนั้นสั่ง AI ให้แปลงเฉพาะไฟล์ใหม่

ตรวจ: ทุกรายการที่ติ๊ก - [x] แล้วมี PDF ตามชื่อที่ระบุใน literature/pdf/ และมี Markdown คู่กันใน literature/markdown/

Workshop 3

ทะเบียนการอ้างอิง: ตรวจว่า cite ถูกต้องกับฉบับเต็ม และคุณภาพของชุดอ้างอิง

ใน workshop นี้คุณจะให้ AI สร้างทะเบียนการอ้างอิงและสรุปคุณภาพของชุดอ้างอิงของบทความจำลอง ตรวจรายการเสี่ยงกับฉบับเต็มด้วยตนเอง แล้วแจ้งว่าเสร็จ Module 4

ก่อนเริ่ม (ต้องมีอยู่แล้ว)

  • module-04-work/input/markdown/paper.md และ module-04-work/output/refs.bib — สร้างในกิจกรรม bibtex-with-openalex-abstracts
  • literature/markdown/ ที่มีฉบับเต็มบางรายการ และ module-04-work/output/manual-download.md — สร้างในกิจกรรม open-access-fulltext-library
  • course-materials/module-04/citation-register-template.csv และ course-materials/module-04/citation-audit-rules.md (ตัวติดตั้ง Module 1 วางไว้ให้ อ่านอย่างเดียว ถ้ายังไม่มี ให้ AI รันเครื่องมือ AIRR materials module-4)
  • (ถ้าทำแล้ว) module-04-work/output/two-layer-precheck.md จากหัวข้อ "ตรวจสองชั้น: ref มีจริง กับ cite ถูกต้อง (สี่ชั้นของแหล่ง หกสถานะ ref ทิพย์)" ใช้เป็นรายการเสี่ยงตั้งต้น
  • ทบทวนจากสไลด์ Module 4: อ่านฉบับเต็มอย่างไรให้ตัดสินได้ (สไลด์ 14) และคุณภาพของชุดอ้างอิง (สไลด์ 16)

คำที่ใช้ใน workshop นี้

  • in-text citation — จุดที่อ้างในเนื้อหา เช่น (Smith, 2020) ซึ่งต้องจับคู่กับรายการท้ายบทความ
  • ref มีจริง / cite ถูกต้อง — สองชั้นของการตรวจ: เอกสารมีอยู่จริงและ metadata ตรง / ข้อความรอบ citation ตรงกับสิ่งที่เอกสารเขียน
  • checked_against — บอกว่าตัดสินชั้น cite ถูกต้องจาก full_text หรือแค่ abstract
  • หกสถานะ — verified, partially supported, not supported, not found, outdated or superseded, fabricated / phantom
  • decision — สิ่งที่จะทำกับข้อความที่อ้าง: เก็บ ลดขอบเขตข้อความ ตัดออก หรือหาแหล่งแทน

ขั้นที่ 1 — ให้ AI สร้างทะเบียนและสรุปคุณภาพ

วาง Prompt นี้ใน AI — AI จะสร้าง module-04-work/output/citation-register.csv และ module-04-work/output/citation-register-summary.md

จาก module-04-work/input/markdown/paper.md และ module-04-work/output/refs.bib ให้หา in-text citation ทุกจุดในเนื้อหา จับคู่กับรายการอ้างอิง แล้วสร้าง module-04-work/output/citation-register.csv ตามหัวคอลัมน์ใน course-materials/module-04/citation-register-template.csv และความหมายของแต่ละคอลัมน์ใน course-materials/module-04/citation-audit-rules.md หนึ่งแถวต่อหนึ่งรายการอ้างอิง ใส่ทุกตำแหน่งที่ถูกอ้างและประโยครอบ citation ถ้ามีฉบับเต็มใน literature/markdown/ ให้เทียบกับฉบับเต็มพร้อมหน้า และตั้ง checked_against เป็น full_text ถ้าไม่มีให้เทียบกับ abstract และตั้งเป็น abstract แล้วระบุว่ารองรับ รองรับบางส่วน ไม่รองรับ หรือตรวจไม่ได้ แยก citation ที่ไม่มีในรายการอ้างอิง และรายการที่ไม่ถูกอ้าง จากนั้นตรวจคุณภาพของชุดอ้างอิงตามตารางคุณภาพใน citation-audit-rules.md แล้วสร้าง module-04-work/output/citation-register-summary.md ที่นับจำนวนตามสถานะ ระบุรายการเสี่ยง และปัญหาคุณภาพของชุดอ้างอิง ห้ามตัดสินจากชื่อเรื่อง แล้วหยุดรอ

ตรวจ: แถวแรกของ citation-register.csv เหมือนแถวแรกของ citation-register-template.csv ทุกคอลัมน์ ทุก entry ใน refs.bib มีแถวของตัวเอง (ดูจาก citation_key) และ citation-register-summary.md มีตารางนับจำนวนตามสถานะ

ขั้นที่ 2 — อ่านทะเบียนแบบผู้ตรวจ

เปิด citation-register.csv ที่ AI เพิ่งสร้าง แล้วดูว่า

  • ชั้น "ref มีจริง" (identity_check, search_sources, retracted) แยกจากชั้น "cite ถูกต้อง" (support, checked_against)
  • รายการที่ถูกอ้างหลายจุดมีทุกตำแหน่งใน cited_at เพราะรายการเดียวอาจอ้างถูกในจุดหนึ่งแต่อ้างเกินในอีกจุดหนึ่ง
  • ไม่มีรายการ not found ที่ถูกเปลี่ยนเป็น fabricated / phantom ทั้งที่ search_sources มีแหล่งเดียว

ตรวจ: ทุกแถวมีค่าใน checked_against และทุกแถวที่ status เป็น fabricated / phantom มีมากกว่าหนึ่งแหล่งใน search_sources (ถ้าไม่ใช่ ให้จดไว้แก้ในขั้นที่ 4)

ขั้นที่ 3 — ตรวจรายการเสี่ยงกับฉบับเต็มด้วยตนเอง

เลือกรายการที่ไม่มี abstract อย่างน้อยหนึ่งรายการ (ถ้ามีเวลา 3 รายการ) ดูว่าข้อความที่ถูกอ้างเป็นชนิดใด แล้วเปิดส่วนที่ตอบได้ตรงที่สุดใน literature/markdown/

ชนิดข้อความที่ถูกอ้าง อ่านส่วนใดของต้นฉบับ ตรวจอะไร
ข้อเท็จจริงหรือนิยาม Introduction หรือส่วนที่นิยาม ความหมายตรงกันหรือไม่
ตัวเลขหรือขนาดผล Results, ตาราง, รูป ค่า หน่วย กลุ่ม และช่วงความเชื่อมั่นตรงหรือไม่
ความสัมพันธ์หรือเหตุและผล Methods และ Discussion รูปแบบการศึกษารองรับการอ้างเหตุและผลหรือไม่
การขยายผลไปกลุ่มอื่น Methods (ประชากร) และ Limitations กลุ่มที่ศึกษาตรงกับกลุ่มที่อ้างหรือไม่
ข้อเสนอแนะหรือมาตรฐาน Conclusion หรือประกาศทางการ เป็นข้อเสนอของผู้เขียน หรือข้อบังคับจริง

ตอบสี่คำถาม: ประชากรและบริบทตรงหรือไม่ ทิศทางและขนาดของผลตรงหรือไม่ ข้อความอ้างแรงกว่าต้นฉบับหรือไม่ (เช่น "บาง" กลายเป็น "ทุก") และข้อเสนอแนะถูกเขียนให้เป็นข้อบังคับ หรือความสัมพันธ์ถูกเขียนให้เป็นเหตุและผลหรือไม่

ถ้าตอบไม่ได้เพราะไม่มีฉบับเต็ม ให้คงสถานะ not found ในชั้น cite ถูกต้อง และใส่ใน manual-download.md

ตรวจ: สำหรับรายการที่ตรวจ คุณชี้ได้ว่าคำตอบสี่ข้อมาจาก page marker หรือส่วนใดใน literature/markdown/<citation_key>.md หรือรายการนั้นอยู่ใน manual-download.md

ขั้นที่ 4 — แก้ทะเบียนเอง

ในแถวที่คุณตรวจ: แก้ checked_against เป็น full_text ใส่หน้าหรือส่วนของต้นฉบับใน support กำหนดสถานะใหม่ ใส่ decision ตามตาราง และใส่ชื่อของคุณในช่อง reviewer

การตัดสินใจ ใช้เมื่อ
เก็บ verified
ลดขอบเขตข้อความ partially supported: แก้ข้อความให้แคบเท่าที่ต้นฉบับรองรับ
ตัดออก not supported, retracted หรือ fabricated
หาแหล่งแทน not found, outdated หรือข้อความยังต้องการหลักฐาน

ตรวจ: อย่างน้อยหนึ่งแถวมี checked_against = full_text หน้าหรือส่วนใน support สถานะเป็นหนึ่งในหกสถานะ มี decision และชื่อคุณใน reviewer

  • ระบุว่า AI ตัดสินต่างจากคุณในแถวใด และคุณแก้อย่างไร
