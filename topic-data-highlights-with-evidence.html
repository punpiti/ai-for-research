Workshop

จากข้อมูลสู่ highlights ที่ตรวจย้อนได้

ใน workshop นี้คุณจะสร้างกราฟและ highlights 3–5 ข้อจากข้อมูล PM2.5 จำลอง ตรวจตัวเลขกับ CSV ด้วยตนเอง แล้วส่งงานผ่าน AIRR ให้ผู้สอนตรวจ

ก่อนเริ่ม (ต้องมีอยู่แล้ว)

  • ผ่านสองหัวข้อก่อนหน้า และมีภาพอย่างน้อยหนึ่งภาพใน module-07-work/figures/
  • มี course-materials/module-07/examples/figure-consistency/mock-study-data.csv และ .venv-module07
  • เปิด AI panel ใน VS Code และเชื่อม AIRR แล้ว

คำที่ใช้ใน workshop นี้

  • highlight — ข้อค้นพบสั้นที่มีตัวเลข หน่วย ฐานเปรียบเทียบ n และขอบเขตข้อสรุป
  • provenance — ที่มาของตัวเลขและขั้นตอนที่ใช้คำนวณ
  • red team — การตรวจเพื่อหาจุดที่กราฟ ข้อความ และข้อมูลต้นทางไม่ตรงกัน
  • submission — ชุดไฟล์ที่ AIRR ส่งให้ผู้สอนตรวจ ไม่รวมข้อมูลวิจัยต้นฉบับ

ขั้นที่ 1 — ตรวจ intake ก่อนวิเคราะห์

ให้ AI อ่าน CSV แบบอ่านอย่างเดียว แล้วสร้าง module-07-work/import-report.md ระบุจำนวนแถว/คอลัมน์ ชื่อคอลัมน์ ชนิดข้อมูล missing/duplicate หน่วยวิเคราะห์ ระดับการรวมค่า และคำเตือน จากนั้นเปิด CSV ตรวจชื่อคอลัมน์และสุ่มเทียบอย่างน้อยสามแถว

ตรวจ: รายงานแยกสิ่งที่อ่านจากไฟล์ สิ่งที่อนุมาน และสิ่งที่ยังไม่รู้; จำนวนแถว/คอลัมน์ตรงกับไฟล์จริง

ขั้นที่ 2 — สร้างกราฟและ highlights

ให้ AI ใช้คำถามกับกราฟที่คุณเลือก สร้างสคริปต์ใน module-07-work/ รันด้วย Python ของโมดูล และบันทึกภาพใน module-07-work/figures/ จากนั้นเขียน module-07-work/module-07-highlights.md จำนวน 3–5 ข้อ แต่ละข้อมีข้อความหลัก ตัวเลข หน่วย ฐานเปรียบเทียบ n ช่วงความไม่แน่นอน ข้อจำกัด และตำแหน่งใน CSV/โค้ดที่ตรวจย้อนกลับได้

ตรวจ: เปิด CSV หรือใช้สคริปต์คำนวณแยก ตรวจตัวเลขใน highlights อย่างน้อยสามค่าด้วยตนเอง

ขั้นที่ 3 — Red team กราฟกับข้อความ

ตรวจเจ็ดเรื่อง: แกนและหน่วย, ตัวหาร, n, ชนิด interval, สี, claim title และตัวเลขย้อนกลับไป CSV ให้ AI ช่วยค้นจุดเสี่ยงได้ แต่ผู้เรียนต้องเปิดไฟล์และตัดสินเอง บันทึกผลใน module-07-work/figure-audit.md

ตรวจ: audit มีตำแหน่ง หลักฐาน สถานะ และการแก้ของทุกข้อ; จุดที่ยังตรวจไม่ได้ระบุว่า BLOCKED

ขั้นที่ 4 — ส่งงานผ่าน AIRR

สั่ง AI ว่า “ส่งงาน Module 7 ให้ฉัน” AI ต้องตรวจไฟล์ก่อน แสดงรายการไฟล์ที่จะส่ง ขอคำยืนยันหนึ่งครั้ง แล้วจึงส่ง module-07-highlights.md กับภาพใน module-07-work/figures/ ห้ามส่ง CSV ต้นฉบับหรือ AIRR Key

ตรวจ: AI รายงาน submission ID และสถานะปัจจุบันโดยไม่แสดง AIRR Key

Exploring

จากข้อมูลสู่ highlights ที่ตรวจย้อนได้

ใช้ข้อมูลของคุณที่นำเข้า AI ได้ตามสิทธิ์ หรือใช้ข้อมูลจำลองชุดสำรอง เขียน prompt เองทั้งหมด

โจทย์

  1. ทำ intake report และ data dictionary ก่อนวิเคราะห์
  2. สร้างกราฟอย่างน้อยหนึ่งภาพและ highlights 3–5 ข้อ
  3. ตรวจเลขกับข้อมูลต้นทางอย่างน้อยสามค่า แล้ว red team กราฟกับข้อความ

ข้อกำหนด

  • เก็บข้อมูลต้นฉบับใน input/original/ และห้ามแก้
  • เก็บ prompt ทุกรอบใน module-07-work/output/prompts.md
  • ไม่อัปโหลดข้อมูลลับ ข้อมูลส่วนบุคคล หรือข้อมูลที่ไม่มีสิทธิ์ให้บริการภายนอก

เสริม · Workshop

ตรวจความสอดคล้องของภาพ ตาราง และข้อความทั้งเอกสาร

ใน workshop นี้คุณจะตรวจบทความจำลองหาความไม่สอดคล้องระหว่าง Methods ตาราง รูป caption และข้อสรุปด้วยตัวเองก่อน ใช้ AI เป็นผู้ตรวจคนที่สอง แล้วกรอกผลลง module-07-work/module-07-figure-audit.md

ทำตามได้ครบด้วยบทความจำลองที่ฝังข้อผิดพลาดไว้เพื่อการเรียน (ข้อมูล PM2.5 จำลองชุดเดียวกัน) ไม่ต้องสร้าง mock เพิ่ม

ก่อนเริ่ม (ต้องมีอยู่แล้ว)

  • ผ่าน Module 1: เปิด ai-for-research-workspace ใน VS Code และ AI panel เชื่อมแล้ว
  • ไฟล์ที่ติดตั้งมากับ Module 1 (อ่านอย่างเดียว):
    • course-materials/module-07/examples/figure-consistency/mock-article-figure-consistency.pdf
    • course-materials/module-07/examples/figure-consistency/mock-study-data.csv
  • module-07-work/module-07-figure-audit.md (ตัวติดตั้ง Module 1 คัดลอกจาก figure-consistency-audit-template.md ไว้ให้ เป็นแม่แบบที่ยังไม่กรอก)
  • ห้ามเปิดสคริปต์สร้างกรณีศึกษาหรือเฉลยผู้สอนก่อนส่งงาน

ขั้นตอน

  1. รอบแรกทำเอง (ไม่ใช้ AI): อ่านบทความจำลองทั้งฉบับ แล้วเทียบ Methods, ตาราง, รูป, caption และข้อสรุป ไล่ตามหมวดในแม่แบบ

    • สีและความหมายของภาพ: สีเดียวกันแทนสิ่งเดียวกันทุกภาพหรือไม่ lower/higher หรือ positive/negative มีความหมายคงที่หรือไม่
    • Population ตัวหาร และการคัดออก: จำนวน observation ที่คาดจากข้อมูล เทียบกับที่รายงาน กลุ่มหรือ site ที่หายไป
    • สถิติและการแปลงค่า: mean/median/rate/change/cumulative ที่แต่ละส่วนใช้ นิยาม change และทิศทางเครื่องหมาย
    • Scale: panel หรือภาพใดใช้ช่วงแกนไม่เหมือนกัน
    • ข้อความ–ตาราง–รูป: ข้อความใดไม่ตรงกับตารางหรือรูป caption ใดกล่าวเกินข้อมูล

  2. กรอก Cross-figure issue ledger ใน module-07-work/module-07-figure-audit.md ให้มีอย่างน้อย 6 ประเด็น โดยอย่างน้อย 4 ประเด็นต้องอาศัยการอ่านตั้งแต่สองตำแหน่งขึ้นไป ระบุหน้า รูป ตาราง คอลัมน์ หรือการคำนวณที่รองรับ

  3. ตรวจค่าจาก CSV ด้วยตนเองอย่างน้อย 3 ค่า (เช่น จำนวน observation ต่อกลุ่มที่บทความรายงาน)

  4. รอบสองใช้ AI เป็นผู้ตรวจคนที่สอง ตัวอย่าง prompt

    อ่าน mock-article-figure-consistency.pdf และ mock-study-data.csv โดยไม่แก้ไฟล์ หาความไม่สอดคล้องระหว่าง Methods ตาราง รูป caption และข้อสรุป ที่เปลี่ยนข้อสรุป (สี นิยาม ทิศทางเครื่องหมาย สถิติ กลุ่มข้อมูล ช่วงแกน population) ไม่นับเรื่องความสวยงาม แต่ละประเด็นระบุตำแหน่งที่ต้องอ่านร่วมกันและหลักฐานจากข้อมูล ยังไม่ต้องเขียนลงไฟล์ของฉัน

  5. เทียบผลของ AI กับ ledger ของคุณ ตัดสินเองว่าจะเพิ่มประเด็นใด (ตรวจหลักฐานทุกข้อที่ AI เสนอก่อนรับ) และทำเครื่องหมาย AI used after the human-first pass: yes

  6. เขียน Executive diagnosis และ Minimum corrected claim ในแม่แบบ

ตรวจก่อนจบ

ส่งงาน

  • ระบบรับงานของ Module 7 (AIRR) รับเฉพาะ module-07-highlights.md และกราฟ ไฟล์ figure audit เก็บไว้ใน workspace เพื่อคุยกับผู้สอน

เสริม · Exploring

ตรวจความสอดคล้องของภาพ ตาราง และข้อความทั้งเอกสาร

ใน Exploring workshop นี้คุณจะตรวจเอกสารหนึ่งชิ้นที่มีหลายรูปและตารางหาความไม่สอดคล้องด้วยตัวเองก่อน แล้วเขียน prompt เองให้ AI เป็นผู้ตรวจคนที่สอง ได้ ledger ใน module-07-work/output/figure-consistency-audit.md

ผู้เรียนเขียน prompt เอง ไม่มี prompt สำเร็จรูปให้

ก่อนเริ่ม (ต้องมีอยู่แล้ว)

  • ผ่าน Module 1: เปิด ai-for-research-workspace ใน VS Code และ AI panel เชื่อมแล้ว · โฟลเดอร์ module-07-work/ (ตัวติดตั้ง Module 1 สร้างไว้)
  • แม่แบบ course-materials/module-07/examples/figure-consistency/figure-consistency-audit-template.md (ติดตั้งมากับ Module 1 · อ่านอย่างเดียว)
  • เอกสารหนึ่งชิ้นที่มีหลายรูปและตาราง (ร่างบทความของคุณ วิทยานิพนธ์ของนิสิต หรือบทความที่เผยแพร่และเปิดข้อมูล) ที่มีสิทธิ์นำเข้า AI — ตรวจสิทธิ์ก่อนนำ manuscript ที่ยังไม่เผยแพร่เข้า AI
    • ถ้ายังไม่มี: ใช้บทความจำลอง course-materials/module-07/examples/figure-consistency/mock-article-figure-consistency.pdf คู่กับ mock-study-data.csv ในโฟลเดอร์เดียวกัน (ติดตั้งมากับ Module 1)

ขั้นตอน

  1. สร้างโฟลเดอร์ module-07-work/output/ และไฟล์ module-07-work/output/prompts.md (ถ้ามีจาก Exploring workshop ข้ออื่นแล้ว ให้เพิ่มหัวข้อใหม่ต่อท้าย) ไว้จดทุกรอบเป็น prompt → สรุปคำตอบของ AI → สิ่งที่คุณตัดสินใจ
  2. คัดลอกแม่แบบไปเป็น module-07-work/output/figure-consistency-audit.md (ใช้โครงนี้ได้ ไม่บังคับ)
  3. ทำรอบแรกเองโดยไม่ใช้ AI: หาความไม่สอดคล้องระหว่าง Methods ตาราง รูป caption และข้อสรุป ที่เปลี่ยนข้อสรุป แล้วบันทึกลง ledger
  4. ถ้ามีข้อมูลต้นทาง ตรวจค่าอย่างน้อย 3 ค่า
  5. เขียน prompt ให้ AI เป็นผู้ตรวจคนที่สอง แล้วตัดสินเองว่ารับประเด็นใด (ตรวจหลักฐานก่อนรับ) และทำเครื่องหมายว่าประเด็นใดมาจาก AI
  6. เขียนข้อสรุปฉบับแก้ 2–4 ประโยคในไฟล์เดียวกัน

ข้อกำหนด

  • เขียน prompt เองทุกข้อ ไม่ใช้ prompt สำเร็จรูปจาก workshop และจดทุกรอบใน module-07-work/output/prompts.md
  • ระบุว่าตรวจผลของ AI อย่างไร (เปิดภาพดูเอง คำนวณเอง หรือเปิดข้อมูลต้นทาง) และแก้อะไรเอง
  • ข้อมูลที่ไม่มีสิทธิ์นำเข้า AI (ข้อมูลส่วนบุคคล ข้อมูลลับ manuscript ที่ยังไม่เผยแพร่) ให้ใช้ข้อมูลจำลอง/ข้อมูลเปิดแทน
  • ถ้า AI เสนอวิธีทางสถิติที่คุณอธิบายเหตุผลไม่ได้ ให้หยุดและปรึกษาผู้เชี่ยวชาญก่อนใช้ผล
