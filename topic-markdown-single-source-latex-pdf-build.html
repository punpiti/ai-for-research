Workshop

ต้นฉบับ Markdown ชุดเดียว → LaTeX ที่ AI สร้าง → PDF และการแก้ build ตามชั้น

ใน workshop นี้คุณจะใส่รูปลงต้นฉบับ Markdown ให้ AI สร้าง LaTeX ตามข้อกำหนดของวารสารจำลอง Journal A แล้ว build เป็น PDF และแก้ build ที่พังตามชั้น — ได้ generated/main.tex และ build/manuscript.pdf (ใช้ต้นฉบับ PM2.5 จำลองและระเบียนอ้างอิงจำลองทั้งหมด)

ก่อนเริ่ม (ต้องมีอยู่แล้ว)

  • ผ่าน Module 1: เปิด ai-for-research-workspace ใน VS Code และ AI panel เชื่อมแล้ว (ตัวติดตั้ง Module 1 ติดตั้ง latexmk และ xelatex ให้)
  • ไฟล์เหล่านี้ (ตัวติดตั้ง Module 1 สร้างไว้ให้ ถ้าไม่พบ ให้สั่ง AI รัน AIRR init module-8 ครั้งเดียว) (คัดลอกมาจาก course-materials/module-08/):
    • module-08-work/source/manuscript.md — ต้นฉบับ ถ้าทำหัวข้อ “จาก highlights สู่ย่อหน้า: ข้อตกลงของย่อหน้าและการตรวจย้อนทุกประโยค” แล้ว จะมีย่อหน้า Results/Limitations ของคุณอยู่ ถ้ายังไม่ทำ ไฟล์นี้ยังเป็น starter ที่มีแต่หัวข้อกับคำแนะนำ ใช้ฝึกได้เหมือนกัน
    • module-08-work/literature/references.bib และ module-08-work/figures/pm25-before-after.png
    • module-08-work/input/module-07-highlights.md — highlights (ของคุณจาก Module 7 หรือฉบับตัวอย่าง) ใช้ตรวจจำนวนตัวอย่างใน caption
    • module-08-work/journal-dossiers/journal-a/original/profile.md — ข้อกำหนด Journal A
  • (ไม่บังคับ) ตัวอย่าง .tex สำหรับเทียบรูปแบบเท่านั้น ห้ามคัดลอกไปเป็นงาน: module-08-mock-report.tex

คำที่ใช้ใน workshop นี้

  • source of truth — ต้นฉบับชุดเดียวที่ใช้แก้เนื้อหา ในโมดูลนี้คือ source/manuscript.md
  • generated — LaTeX ที่ AI สร้างใหม่ได้จาก Markdown ไม่ใช่ที่แก้เนื้อหาหลัก
  • build — PDF และ log ที่ได้จากคำสั่งสร้างเอกสาร
  • build log — บันทึก warning/error ที่ใช้หาชั้นของปัญหา

ขั้นตอน

  1. ดูสายการผลิต (1 นาที) เปิดโฟลเดอร์ module-08-work/ ใน Explorer แล้วดูว่า source/ คือที่คุณแก้ generated/ คือที่ AI จะสร้างไฟล์ LaTeX (สร้างใหม่ได้ทุกเมื่อ) และ build/ คือที่ PDF กับ log จะไปอยู่ — ตอนนี้ generated/ และ build/ ยังว่าง

    ตรวจ: อธิบายได้ว่าเนื้อหาแก้ที่ source/ ส่วน generated/ กับ build/ สร้างใหม่ได้

  2. ใส่รูปใน Markdown เปิด source/manuscript.md ใต้หัวข้อ Results เขียนตำแหน่งรูป caption ป้ายอ้างถึง และแหล่งที่มา แล้วอ้างรูปจากข้อความ caption ที่ดีบอกสิ่งที่วัด กลุ่ม หน่วย จำนวนตัวอย่าง และชนิดของความไม่แน่นอน (ตรวจจำนวนตัวอย่างจาก input/module-07-highlights.md: 120 observations ต่อ arm-period, 40 ต่อ site-arm-period)

    ตรวจ: Markdown อ้างรูปและ caption มีสิ่งที่วัด กลุ่ม หน่วย n และ interval

  3. ให้ AI สร้าง LaTeX ส่ง prompt นี้ AI จะสร้าง module-08-work/generated/main.tex

    ใช้ module-08-work/source/manuscript.md เป็น source of truth สร้าง module-08-work/generated/main.tex ตามข้อกำหนดใน module-08-work/journal-dossiers/journal-a/original/profile.md (หัวข้อ, author–year citations และ BibTeX, ฉบับ review ไม่มีชื่อผู้แต่ง) เชื่อม module-08-work/literature/references.bib และรูปใน module-08-work/figures/ ใช้เฉพาะเนื้อหาที่อยู่ใน Markdown ห้ามเพิ่มผล ตัวเลข citation หรือขั้นตอนวิธีที่ไม่มีในต้นฉบับ ห้ามแก้ generated LaTeX เป็นเนื้อหาหลัก รายงานว่าหัวข้อใดใน Markdown ไปอยู่ส่วนใดของ .tex แล้วหยุดรอ

    อ่านรายงานของ AI แล้วดูว่าทุกหัวข้อใน manuscript.md มีที่อยู่ใน main.tex

    ตรวจ: generated/main.tex มีเนื้อหาเฉพาะที่อยู่ใน Markdown และเชื่อม BibTeX กับรูปถูกตำแหน่ง

  4. build PDF วาง prompt นี้ในแชต AI แล้วรอ AI รายงาน (ไม่ต้องเปิด Terminal)

    build PDF ของ Module 8: ในโฟลเดอร์ module-08-work/ รัน latexmk -xelatex -bibtex -interaction=nonstopmode -halt-on-error -jobname=manuscript -outdir=build generated/main.tex (ใช้ latexmk ของ TinyTeX ที่ตัวติดตั้งหลักสูตรวางไว้ ถ้าไม่พบใน PATH ให้หาในโฟลเดอร์ TinyTeX ของหลักสูตร) คำสั่งนี้สร้าง module-08-work/build/manuscript.pdf และ log ใน module-08-work/build/ รายงานว่า build สำเร็จไหม และสรุป error/warning จาก log (โดยเฉพาะ undefined citation และรูปที่หาไม่พบ) ฉันอนุญาตให้สร้างไฟล์ใน module-08-work/build/ ได้ แต่ห้ามแก้ไฟล์ใน source/ literature/ figures/ และ generated/ แล้วหยุดรอ

    จากนั้นเปิด module-08-work/build/manuscript.pdf ใน VS Code (คลิกในแถบไฟล์ด้านซ้าย)

    ตรวจ: PDF เปิดได้ และ log ไม่มี undefined citation

  5. ถ้า build พัง ให้แก้ตามชั้น ให้ AI อ่าน log แล้วชี้ชั้นที่เป็นปัญหาก่อนแก้

    อ่าน log ใน module-08-work/build/ บอกว่าปัญหาอยู่ชั้นใด: เนื้อหาใน Markdown, citation key กับ references.bib, ชื่อ/ตำแหน่งรูปใน figures/, หรือ environment/package เสนอการแก้ที่ไฟล์ต้นทาง ห้ามแก้ PDF ห้ามแก้ generated/main.tex แทนต้นฉบับ ห้ามดาวน์โหลด package จากแหล่งไม่ทราบที่มา แล้วหยุดรอให้ฉันอนุมัติ
    อาการ ตรวจชั้นใดก่อน ห้ามทำ
    Missing generated/main.tex ยังไม่ได้ให้ AI สร้างจาก Markdown (ขั้น 3) เขียน .tex เอง
    citation หรือ reference ขึ้นเป็น ? citation key ใน Markdown กับ references.bib แก้เลขใน PDF ด้วยมือ
    หารูปไม่พบ ชื่อและตำแหน่งไฟล์ใน figures/ แก้ generated/main.tex แทนต้นฉบับ
    latexmk หรือ xelatex หายไป รันตัวติดตั้ง Module 1 ซ้ำ แล้วสั่ง AI รัน AIRR init module-8 ดาวน์โหลด package จากแหล่งสุ่ม

    ตรวจ: ระบุชั้นของปัญหาก่อนแก้ และแก้ที่ source, literature, figures หรือ environment ตามหลักฐานจาก log

  6. (ถ้ามีเวลา) ลองทำพังแล้วซ่อม ถ้า source/manuscript.md มี citation key อยู่แล้ว (เช่น Arun2024CommunityPM จาก references.bib) แก้ key หนึ่งตัวให้ผิด เช่น ตัดปีออก ให้ AI สร้าง main.tex ใหม่และ build — ดูว่า PDF แสดง ? และ log เตือนอะไร แล้วแก้กลับที่ Markdown ไม่ใช่ที่ PDF แล้ว build อีกครั้ง

    ตรวจ: key ถูกแก้กลับที่ Markdown และ PDF ล่าสุดไม่มี ?

ตรวจก่อนจบ

ข้อจำกัดของ mock

  • Journal A จำลองไม่มี LaTeX author kit จริง จึงฝึกด่าน “ทดสอบแม่แบบเดิม (pristine template)” ไม่ได้ — งานจริงต้อง compile template ทางการก่อนใส่เนื้อหา และเก็บ PDF/log เป็น baseline

ส่งงาน

  • ส่งตามขั้นตอนส่งงานของโมดูล (ตอนนี้ Module 8 ยังไม่กำหนดช่องทางส่ง)

Exploring

ต้นฉบับ Markdown ชุดเดียว → LaTeX ที่ AI สร้าง → PDF และการแก้ build ตามชั้น

ในโจทย์นี้คุณจะเขียน prompt เอง (ไม่มี prompt สำเร็จรูปให้) เพื่อเปลี่ยนเอกสารสั้นของตัวเองเป็นต้นฉบับ Markdown ชุดเดียว ให้ AI สร้าง LaTeX ตามแม่แบบของแหล่งเผยแพร่ที่เลือก แล้ว build เป็น PDF พร้อมบันทึกการแก้ build

ก่อนเริ่ม (ต้องมีอยู่แล้ว)

  • ทำ workshop หลักของหัวข้อนี้แล้ว: build module-08-work/build/manuscript.pdf ได้ (ให้ AI รัน latexmk ตามขั้น build PDF ของ workshop หลัก)
  • เอกสารสั้นของคุณเอง 2–4 หน้า (รายงานความก้าวหน้า บทคัดย่อขยาย หรือหนึ่งส่วนของบทความ) ที่มีอย่างน้อย 1 รูปและ 2 citation พร้อมไฟล์รูปและข้อมูลอ้างอิงของ citation เหล่านั้น
  • แม่แบบ LaTeX ทางการของแหล่งเผยแพร่ที่คุณเลือก ดาวน์โหลดจากเว็บของแหล่งเผยแพร่นั้นเอง (ถ้าแหล่งเผยแพร่กำหนด Word ให้ระบุเหตุผลและเลือกแหล่งที่ใช้ LaTeX สำหรับแบบฝึกนี้)

โจทย์

  1. สร้างโฟลเดอร์ output/ สำหรับงานนี้ และเริ่มไฟล์ output/prompts.md ไว้บันทึก prompt ทุกรอบ
  2. เขียนเนื้อหาเป็น Markdown ต้นฉบับชุดเดียวที่ output/source/manuscript.md วางรูปใน output/figures/ และทำ output/references.bib
  3. เขียน prompt ให้ AI สร้าง output/generated/main.tex ตามแม่แบบที่ดาวน์โหลดมา
  4. build เป็น PDF ใน output/build/ และแก้ปัญหา build อย่างน้อยหนึ่งครั้งตามชั้น (Markdown / citation key กับ .bib / รูป / environment) บันทึกลง output/repair-log.md ที่คุณสร้างในขั้นนี้ (อาการ → ชั้นที่ตรวจ → ไฟล์ต้นทางที่แก้)

ข้อกำหนด

  • output/prompts.md เก็บ prompt ทุกรอบ (prompt, สรุปผลที่ได้, สิ่งที่ปรับในรอบถัดไปและเหตุผล)
  • ระบุว่าตรวจผลของ AI อย่างไร (เทียบกับไฟล์/เอกสารต้นทางใด) และแก้อะไรเอง
  • ผลงาน: output/source/manuscript.md, output/references.bib, output/figures/, output/generated/main.tex, output/build/*.pdf และ output/repair-log.md
  • ใช้แม่แบบจากแหล่งทางการเท่านั้น และไม่แก้ .cls/.sty/.bst ของแหล่งเผยแพร่
