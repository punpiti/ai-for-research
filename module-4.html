ก่อนค้น

แหล่งที่ช่วย “พบ” ไม่จำเป็นต้องเป็นหลักฐาน

01

Discovery Source

Search engine, AI, review หรือรายการแนะนำช่วยให้พบชื่อเรื่อง แต่ยังไม่ยืนยันว่าแหล่งมีอยู่จริงหรือสนับสนุน claim

02

Metadata Source

OpenAlex, Crossref, DOI registry หรือฐานข้อมูลบรรณานุกรมช่วยค้นและตรวจชื่อ ผู้แต่ง ปี วารสาร และ DOI แต่ metadata ยังไม่บอกว่าข้อความในบทความสนับสนุน claim

03

Official Page

หน้า publisher, journal, conference หรือ repository ทางการช่วยยืนยันตัวตน เวอร์ชัน และ abstract จากต้นทาง

04

Full-text Evidence

PDF หรือ HTML ฉบับเต็มทำให้ตรวจ method, result, limitation และบริบทของข้อความที่ต้องการอ้างได้

กฎสำคัญ: DOI ที่เปิดได้ยืนยันว่าเอกสารมีอยู่จริง แต่ยังไม่ยืนยันว่าเอกสารนั้นสนับสนุน Claim ต้องอ่านตำแหน่งที่เกี่ยวข้องในต้นฉบับอีกครั้ง

ศัพท์ที่ต้องแยกให้ออก

สี่คำที่ต้องแยกก่อนตรวจการอ้างอิง

AI สร้างรายการอ้างอิงที่ดูสวยและครบได้ง่าย แต่ดูสวยไม่ได้แปลว่าบทความมีอยู่จริงหรือรองรับข้อความของเรา สี่คำนี้ช่วยบอกว่ากำลังตรวจชั้นไหน

In-text citation · การอ้างในเนื้อหา

เครื่องหมายอ้างอิงในเนื้อหา เช่น (Anan, 2025) บอกผู้อ่านให้ไปหารายละเอียดใน reference list แต่ยังไม่บอกว่าผู้เขียนอ้างตรงกับต้นฉบับหรือไม่

Reference entry · รายการอ้างอิงท้ายเรื่อง

รายการท้ายบทความที่แสดงผู้แต่ง ปี ชื่อเรื่อง และแหล่งพิมพ์ รูปแบบ APA หรือรูปแบบอื่นคือวิธีแสดงผล ไม่ใช่หลักฐานยืนยันความถูกต้อง

DOI · รหัสประจำตัวบทความ

รหัสถาวรที่พาไปยังระเบียนของเอกสาร ช่วยยืนยัน identity และ metadata แต่ DOI ที่ถูกต้องยังไม่พิสูจน์ว่าเนื้อหาสนับสนุน Claim

Abstract และ Full text · บทคัดย่อและฉบับเต็ม

Abstract เป็นบทสรุปที่ผู้เขียนหรือวารสารเผยแพร่ ส่วน full text มีรายละเอียด method, result และ limitation ที่จำเป็นต่อการตรวจการอ้างเชิงลึก

ข้อกำหนดของงานนี้: BibTeX ทุก entry ต้องมี abstract ที่คัดจาก official page หรือ full text ไม่ใช่ข้อความที่ AI สรุปขึ้นใหม่ หากต้นทางไม่มี abstract หรือยังเข้าไม่ถึง ให้บันทึกว่า abstract not found ในรายงานตรวจและกลับมาเติมเมื่อมีหลักฐาน ห้ามแต่งให้ครบ
จำสั้น ๆ: BibTeX เก็บข้อมูลอ้างอิง, DOI ชี้ตัวเอกสาร, citation เชื่อมข้อความไปหาเอกสาร และ full text ใช้ตัดสินว่าเอกสารรองรับข้อความหรือไม่
ส่วนขยาย · BibTeX, metadata และสายการตรวจ Claim → Evidence (ไม่บังคับ)

BibTeX entry

ระเบียนข้อความแบบมีโครงสร้างในไฟล์ .bib ใช้เก็บ field และสร้าง reference list อัตโนมัติ เช่น @article, citation key, author, title, year, DOI และ abstract โดย citation key เป็นชื่อเรียกภายในไฟล์ ไม่ใช่ DOI

Bibliographic metadata

ข้อมูลระบุตัวเอกสาร เช่น ผู้แต่ง ชื่อเรื่อง ปี วารสาร เล่ม ฉบับ หน้า และ DOI ควรเทียบกับ DOI registry, publisher หรือ repository ทางการ

อย่าสับสน: APA คือกติกาการแสดงผล; BibTeX และ RIS คือรูปแบบไฟล์แลกเปลี่ยนข้อมูลอ้างอิง; Zotero หรือ Mendeley คือโปรแกรมจัดการรายการอ้างอิง; DOI คือรหัสระบุตัวเอกสาร สิ่งเหล่านี้ช่วยจัดการข้อมูล แต่ไม่มีอย่างใดใช้แทนการอ่านหลักฐานได้
ตัวอย่างสมมติ—ห้ามนำไปอ้างอิง: ในเนื้อหาอาจเขียน (Anan, 2025) ส่วน reference list และ BibTeX เก็บรายละเอียดของ “อาหารโปรตีนกับความอิ่มในนักศึกษา” เรื่องเดียวกัน ตัวอย่างจึงมี field abstract แต่ยังไม่ใส่ field doi เพราะยังไม่ยืนยัน

01

Claim

ข้อความในงานของเราที่ต้องมีหลักฐานรองรับ

02

Citation

เชื่อม Claim ไปยัง reference entry หรือ citation key ที่ระบุแหล่ง

03

Identity

ใช้ metadata, DOI และ official page ตรวจว่าเอกสารนั้นมีอยู่จริงและเป็นเรื่องเดียวกับที่ระบุ

04

Evidence

กลับไปอ่าน full text เพื่อดูว่าผล วิธี และขอบเขตสนับสนุน Claim จริงเพียงใด

ภาษากลางของบทนี้

หกสถานะสำหรับทุก Citation

verified

แหล่งมีอยู่จริง metadata ตรง และข้อความต้นฉบับสนับสนุน claim ในขอบเขตที่อ้าง

partially supported

สนับสนุนเพียงบางส่วน บริบท ประชากร วิธี หรือระดับความมั่นใจแคบกว่าข้อความที่เขียน

not supported

แหล่งมีอยู่จริง แต่เนื้อหาไม่สนับสนุน claim หรือให้ผลตรงข้าม

not found

ยังหาแหล่งหรือ full text ไม่พบ ต้องบันทึกข้อจำกัด ห้ามเปลี่ยนสถานะเป็น “ไม่มีงาน”

outdated or superseded

แหล่งเคยใช้ได้ แต่มีหลักฐานใหม่ มาตรฐานใหม่ หรือเวอร์ชันที่มาแทน

fabricated / phantom reference

Reference ไม่มีอยู่จริง DOI ผิด หรือ metadata หลายส่วนถูกประกอบขึ้นให้ดูน่าเชื่อ ซึ่งเรียกง่าย ๆ ว่า “ref ทิพย์”

สร้าง BibTeX พร้อม abstract จาก OpenAlex

แกะรายการอ้างอิงทั้งหมด จับคู่กับ OpenAlex แล้วได้ refs.bib ที่บอกตามจริงว่ารายการใดตรง ไม่ตรง หรือไม่พบ

รายการรายละเอียด
เป้าหมายrefs.bib ครบทุกรายการ พร้อม abstract และผลจับคู่จาก OpenAlex
อ่านจากmodule-04-work/input/original/mock-paper.pdf
ได้ไฟล์module-04-work/input/markdown/paper.md, module-04-work/output/refs.bib
ตรวจเองก่อนไปต่อสุ่ม 3 รายการ เปิด DOI หรือหน้าทางการ เทียบ author, year, title และ venue ทีละช่อง

เตรียมไฟล์ (ทำครั้งเดียว)

เปิด Terminal ใน VS Code ที่โฟลเดอร์ ai-for-research-workspace แล้วรันคำสั่งตามระบบ คำสั่งนี้วางบทความจำลองไว้ใน module-04-work/input/original/ และวางกติกาการตรวจ (citation-audit-rules.md) กับแม่แบบทะเบียน (citation-register-template.csv) ไว้ใน course-materials/module-04/ ให้ AI อ่าน

b=https://urban.cpe.ku.ac.th/ai-for-research/downloads/module-04-mock o=module-04-work/input/original; c=course-materials/module-04 mkdir -p "$o" "$c" curl -fsSL "$b/mock-paper.pdf" -o "$o/mock-paper.pdf" for f in citation-audit-rules.md citation-register-template.csv; do curl -fsSL "$b/$f" -o "$c/$f" done
อ่าน course-materials/module-04/citation-audit-rules.md ก่อน แล้วแปลงงานวิจัยใน module-04-work/input/original/ เป็น module-04-work/input/markdown/paper.md พร้อม page marker แล้วแกะรายการอ้างอิง ท้ายเรื่องทั้งหมดตามลำดับ ห้ามเดาชื่อเรื่อง ผู้แต่ง หรือ DOI ที่อ่านไม่ชัด จากนั้นค้นแต่ละรายการใน OpenAlex API ด้วย DOI ก่อน ถ้าไม่มี DOI ให้ค้นด้วยชื่อเรื่องและปี แล้วสร้าง module-04-work/output/refs.bib หนึ่ง entry ต่อหนึ่งรายการ ใส่ abstract ที่ประกอบจาก OpenAlex เท่านั้น พร้อม field abstract_source, openalex_id, identity_check, retracted และ local_fulltext (เว้นว่างไว้ก่อน) ถ้าไม่พบหรือ metadata ไม่ตรง ให้บันทึกตามจริง ห้ามแต่ง abstract ใช้ API key จากตัวแปร OPENALEX_KEY เท่านั้น และห้ามพิมพ์ key ลงไฟล์ log หรือผลลัพธ์ใด สรุปจำนวน matched, metadata_conflict, not_found, abstract not found และ retracted แล้วหยุดรอ

สิ่งที่ควรเห็น: บางรายการ metadata ไม่ตรง บางรายการไม่พบ บางรายการไม่มี abstract และอย่างน้อยหนึ่งรายการถูกถอน ขั้นนี้ตรวจเฉพาะ “ref มีจริง” ยังไม่ต้องตัดสินว่ารายการใดปลอม

ข้อกำหนดของงานนี้: BibTeX ทุก entry ต้องมี abstract ที่ประกอบจาก OpenAlex หรือคัดจากหน้าทางการ ไม่ใช่ข้อความที่ AI สรุปขึ้นใหม่ ถ้าไม่มี ให้บันทึก abstract not found ห้ามแต่งให้ครบ

ดาวน์โหลดผ่านสิทธิ์มหาวิทยาลัยด้วยตนเองเท่านั้น: เชื่อม VPN ของมหาวิทยาลัย เปิดรายการใน manual-download.md ผ่านเบราว์เซอร์ บันทึกตามชื่อไฟล์ที่ระบุ แล้วสั่ง AI แปลงเฉพาะไฟล์ใหม่ ห้ามให้ AI ดาวน์โหลดผ่านสิทธิ์สมาชิกแบบอัตโนมัติ เพราะข้อตกลงกับสำนักพิมพ์ห้าม และ IP ของมหาวิทยาลัยอาจถูกบล็อก คลังนี้ใช้ส่วนตัว ห้ามเผยแพร่ต่อ

Sub-module 4.3 · 15 นาที · บทความจำลอง

ตรวจการอ้างอิงและทำทะเบียน

จับคู่ in-text citation ทุกจุดกับรายการอ้างอิง ตรวจว่าต้นฉบับรองรับข้อความหรือไม่ แล้วดูคุณภาพของชุดอ้างอิงทั้งชุด

รายการรายละเอียด
เป้าหมายทะเบียนที่บอกได้ทุกรายการว่า ref มีจริงหรือไม่ และ cite ถูกต้องหรือไม่ พร้อมสรุปคุณภาพของชุดอ้างอิง
อ่านจากmodule-04-work/input/markdown/paper.md, module-04-work/output/refs.bib, literature/markdown/
ได้ไฟล์module-04-work/output/citation-register.csv, module-04-work/output/citation-register-summary.md
ตรวจเองก่อนไปต่อเลือกรายการที่ไม่มี abstract อย่างน้อยหนึ่งรายการ เปิดฉบับเต็มตรวจเอง แก้ checked_against เป็น full_text และกำหนดสถานะใหม่
จาก module-04-work/input/markdown/paper.md และ module-04-work/output/refs.bib ให้หา in-text citation ทุกจุดในเนื้อหา จับคู่กับรายการอ้างอิง แล้วสร้าง module-04-work/output/citation-register.csv ตามหัวคอลัมน์ใน course-materials/module-04/citation-register-template.csv และความหมายของแต่ละคอลัมน์ใน course-materials/module-04/citation-audit-rules.md หนึ่งแถวต่อหนึ่งรายการอ้างอิง ใส่ทุกตำแหน่งที่ถูกอ้างและประโยครอบ citation ถ้ามีฉบับเต็มใน literature/markdown/ ให้เทียบกับฉบับเต็มพร้อมหน้า และตั้ง checked_against เป็น full_text ถ้าไม่มีให้เทียบกับ abstract และตั้งเป็น abstract แล้วระบุว่ารองรับ รองรับบางส่วน ไม่รองรับ หรือตรวจไม่ได้ แยก citation ที่ไม่มีในรายการอ้างอิง และรายการที่ไม่ถูกอ้าง จากนั้นตรวจคุณภาพของชุดอ้างอิงตามตารางคุณภาพใน citation-audit-rules.md แล้วสร้าง module-04-work/output/citation-register-summary.md ที่นับจำนวนตามสถานะ ระบุรายการเสี่ยง และปัญหาคุณภาพของชุดอ้างอิง ห้ามตัดสินจากชื่อเรื่อง แล้วหยุดรอ

อ่านฉบับเต็มอย่างไรให้ตัดสินได้

ข้อเท็จจริงหรือนิยามIntroductionความหมายตรงกัน
ตัวเลขหรือขนาดผลResults, ตาราง, รูปค่า หน่วย กลุ่ม ช่วงความเชื่อมั่น

คุณภาพของชุดอ้างอิง: สิ่งที่ผู้อ่าน lit review ไม่ชอบ

พึ่งแหล่งเดียวมากเกินไป · อ้างตนเองหรือกลุ่มเดียวกัน · แหล่งไม่น่าเชื่อถือ (ถูกถอน, Wikipedia, รายงานภายใน, ref ทิพย์) · แหล่งเก่าหรือมาตรฐานรุ่นเก่า · ไม่มีงานจากบริบทไทยหรือภูมิภาค · ขาดหลักฐานแย้ง · รายการไม่เรียบร้อย (ปีผิด ขาด DOI มี citation ที่ไม่มีในรายการ)

แจ้งว่าเสร็จ แล้วเฉลยร่วมกัน

การส่งงานของโมดูลนี้เป็นเพียงการแจ้งว่าทำเสร็จ ไม่ส่งทะเบียนหรือเนื้อหางาน ไฟล์ทั้งหมดอยู่ในเครื่องของคุณ

  • 4.1: refs.bib ครบทุกรายการ ช่องที่หาไม่พบระบุตามจริง
  • 4.2: รายการที่ไม่ได้ฉบับเต็มอยู่ใน manual-download.md ครบ
  • 4.3: ทะเบียนแยก “ref มีจริง” ออกจาก “cite ถูกต้อง” ระบุว่ารายการใดตรวจกับฉบับเต็ม รายการใดแค่ abstract และไม่เรียกรายการที่ “ไม่พบ” ว่าเป็น ref ทิพย์ โดยไม่ได้ตรวจหลายแหล่ง

แจ้งว่าเสร็จด้วยคำสั่ง AIRR ใน Terminal ของ VS Code ระบบตรวจในเครื่องว่า 4.1–4.3 มีไฟล์ครบ แล้วส่งเฉพาะสถานะว่าเสร็จและจำนวนนับ ไม่ส่งรายการอ้างอิง abstract หรือทะเบียนออกจากเครื่อง ถ้าทำงานจริงในโฟลเดอร์ย่อย ให้เพิ่ม --file module-04-work/<ชื่องาน>

& .\tools\airr.ps1 check module-4; & .\tools\airr.ps1 submit module-4
bash tools/airr.sh check module-4 && bash tools/airr.sh submit module-4

ถ้ายังไม่ได้เชื่อม AIRR ให้แจ้งผู้สอนตามช่องทางที่ผู้สอนแจ้งแทน ถ้า AIRR แจ้งว่าไม่รู้จัก module-4 ให้รันตัวติดตั้ง Module 1 ซ้ำเพื่ออัปเดตเครื่องมือ ระหว่างเฉลย ให้จดว่าปัญหาใดที่ AI หาเจอ ปัญหาใดที่คุณต้องหาเอง และ AI ตัดสินผิดตรงไหน
