Workshop

ตรวจรายการอ้างอิงภาษาไทย: ไม่พบใน OpenAlex ไม่ได้แปลว่าปลอม

ใน workshop นี้คุณจะให้ AI สร้าง refs.bib และทะเบียนการอ้างอิงของบทความจำลองภาษาไทย ตรวจรายการที่ OpenAlex ไม่พบกับแหล่งไทยด้วยตนเอง และตรวจหนึ่งรายการกับฉบับเต็ม

ใช้เมื่อ: ยังไม่มีงานของนิสิตที่ใช้ทดลองได้ หรือต้องการฝึกกับรายการอ้างอิงภาษาไทยโดยเฉพาะ

บทความจำลอง mock-paper-th.pdf มี 2 หน้า 7 รายการอ้างอิง (เอกสารจำลองเพื่อฝึก ไม่ใช่ผลงานตีพิมพ์จริง ห้ามนำไปอ้างอิง) ใช้งานภาษาไทยที่มีอยู่จริงใน ThaiJO ปนกับปัญหาที่ใส่ไว้ เช่น รายการที่ไม่พบใน OpenAlex แต่มีอยู่จริง ปี พ.ศ. กับ ค.ศ. ชื่อผู้แต่งที่ OpenAlex เก็บเป็นอักษรโรมัน และชื่อเรื่องสองภาษา

ก่อนเริ่ม (ต้องมีอยู่แล้ว)

  • ทำ workshop "สร้าง BibTeX พร้อม abstract จาก OpenAlex" และ "ทะเบียนการอ้างอิงและคุณภาพของชุดอ้างอิง" (หัวข้อ "ทะเบียนตรวจ citation: OpenAlex → full text → register") กับบทความจำลองภาษาอังกฤษแล้ว
  • module-04-work/thai-mock/input/original/mock-paper-th.pdf — บทความจำลองภาษาไทย (ตัวติดตั้ง Module 1 วางไว้ให้ เมื่อหน้าต่างติดตั้งแสดง PRACTICE_FILES_READY) ถ้ายังไม่มี: ให้ AI รันเครื่องมือ AIRR materials module-4 --thai หรือดาวน์โหลดบทความจำลองภาษาไทยจากหน้า Module 4 แล้ววางตามตำแหน่งนี้เอง
  • course-materials/module-04/citation-audit-rules.md และ course-materials/module-04/citation-register-template.csv (ชุดเดิมที่ใช้กับบทความภาษาอังกฤษ อ่านอย่างเดียว)
  • OpenAlex API key ในตัวแปร OPENALEX_KEY ของเครื่อง (ตั้งไว้ก่อนเรียน Module 4)
  • คลัง literature/ เดิม (ใช้ร่วมกับบทความภาษาอังกฤษ)

ทุกขั้นด้านล่างใช้โฟลเดอร์ module-04-work/thai-mock/ แทน module-04-work/ แต่ใช้คลัง literature/ เดิม

คำที่ใช้ใน workshop นี้

  • พ.ศ. / ค.ศ. — ปีพุทธศักราชลบ 543 ได้ปีคริสต์ศักราช ต้องแปลงก่อนเทียบปี
  • ThaiJO / TCI / ThaiLIS — แหล่งค้นวารสารไทยและวิทยานิพนธ์ไทย ใช้เมื่อ OpenAlex ไม่พบ
  • search_sources — ทุกแหล่งที่ค้นแล้วของรายการนั้น เช่น OpenAlex; DOI; ThaiJO; TCI; ThaiLIS
  • identity_check — ผลชั้น "ref มีจริง" ของรายการนั้น
  • not found — ค้นแล้วไม่พบ ไม่ได้แปลว่าปลอม ห้ามเปลี่ยนเป็น fabricated จากการค้นแหล่งเดียว

ขั้นที่ 1 — ให้ AI สร้าง refs.bib ของรายการภาษาไทย

วาง Prompt นี้ใน AI — AI จะสร้าง module-04-work/thai-mock/input/markdown/paper.md และ module-04-work/thai-mock/output/refs.bib

อ่าน course-materials/module-04/citation-audit-rules.md ก่อน โดยเฉพาะหัวข้อรายการภาษาไทย แล้วแปลงงานวิจัยใน module-04-work/thai-mock/input/original/ เป็น module-04-work/thai-mock/input/markdown/paper.md พร้อม page marker แล้วแกะรายการอ้างอิงท้ายเรื่องทั้งหมดตามลำดับ ห้ามเดาชื่อเรื่อง ผู้แต่ง หรือ DOI ที่อ่านไม่ชัด ค้นแต่ละรายการใน OpenAlex API ด้วย DOI ก่อน ถ้าไม่มี DOI ให้ค้นด้วยชื่อเรื่องและปี ทั้งชื่อภาษาไทยและภาษาอังกฤษ แปลงปี พ.ศ. เป็น ค.ศ. (ลบ 543) ก่อนเทียบปี และเทียบชื่อผู้แต่งทั้งอักษรไทยและอักษรโรมัน ถ้าไม่พบใน OpenAlex ให้ค้นต่อใน ThaiJO, TCI และ ThaiLIS สำหรับวิทยานิพนธ์ แล้วบันทึกทุกแหล่งที่ค้นแล้ว สร้าง module-04-work/thai-mock/output/refs.bib หนึ่ง entry ต่อหนึ่งรายการ พร้อม field abstract_source, openalex_id, identity_check, retracted และ local_fulltext (เว้นว่างไว้ก่อน) เก็บ abstract ตามภาษาต้นฉบับและระบุแหล่งที่มา ถ้าไม่พบหรือ metadata ไม่ตรง ให้บันทึกตามจริง ห้ามแต่ง abstract และห้ามเรียกรายการที่ไม่พบว่าปลอม ใช้ API key จากตัวแปร OPENALEX_KEY เท่านั้น และห้ามพิมพ์ key ลงไฟล์ log หรือผลลัพธ์ใด สรุปจำนวน matched, metadata_conflict, not_found, abstract not found และ retracted พร้อมแหล่งที่พบของแต่ละรายการ แล้วหยุดรอ

ตรวจ: refs.bib มี 7 entry และไม่มีรายการใดที่ถูกนับเป็น metadata ไม่ตรงเพียงเพราะปี พ.ศ. ต่างจาก ค.ศ. 543 ปี

ขั้นที่ 2 — ตรวจเองกับแหล่งไทย

เลือกรายการที่ OpenAlex ไม่พบหนึ่งรายการใน refs.bib ค้นเองใน ThaiJO (หรือ TCI / ThaiLIS) ด้วยชื่อเรื่องทั้งสองภาษา แล้วเทียบ author, year (หลังแปลง พ.ศ./ค.ศ.), title และ venue ทีละช่องกับ refs.bib แก้ identity_check และ search_sources ตามที่พบจริง

ตรวจ: คุณเปิดหน้าบทความนั้นใน ThaiJO / TCI / ThaiLIS ได้และชื่อเรื่องตรงกับ refs.bib และ search_sources ของรายการนั้นมีแหล่งไทยที่คุณค้นแล้ว

ขั้นที่ 3 — ให้ AI สร้างทะเบียนการอ้างอิง

วาง Prompt นี้ต่อ — AI จะสร้าง module-04-work/thai-mock/output/citation-register.csv และ citation-register-summary.md (ข้ามการโหลดฉบับเต็มเข้าคลังได้ ฉบับเต็มของบทความใน ThaiJO เปิดจากหน้าวารสารได้)

จาก module-04-work/thai-mock/input/markdown/paper.md และ module-04-work/thai-mock/output/refs.bib ให้หา in-text citation ทุกจุด จับคู่กับรายการอ้างอิง โดยคำนึงว่าการอ้างแบบไทยใช้ชื่อต้นและนามสกุลเต็ม และปีอาจเป็น พ.ศ. แล้วสร้าง module-04-work/thai-mock/output/citation-register.csv ตามหัวคอลัมน์ใน course-materials/module-04/citation-register-template.csv และความหมายของแต่ละคอลัมน์ใน course-materials/module-04/citation-audit-rules.md หนึ่งแถวต่อหนึ่งรายการอ้างอิง ใส่ทุกตำแหน่งที่ถูกอ้างและประโยครอบ citation ถ้ามีฉบับเต็มใน literature/markdown/ ให้เทียบกับฉบับเต็มพร้อมหน้า และตั้ง checked_against เป็น full_text ถ้าไม่มีให้เทียบกับ abstract และตั้งเป็น abstract แล้วระบุว่ารองรับ รองรับบางส่วน ไม่รองรับ หรือตรวจไม่ได้ แยก citation ที่ไม่มีในรายการอ้างอิง และรายการที่ไม่ถูกอ้าง แล้วสร้าง module-04-work/thai-mock/output/citation-register-summary.md ที่นับจำนวนตามสถานะ ระบุรายการเสี่ยง และปัญหาคุณภาพของชุดอ้างอิง ห้ามตัดสินจากชื่อเรื่อง และห้ามเปลี่ยน not found เป็น fabricated จากการค้นแหล่งเดียว แล้วหยุดรอ

ตรวจ: citation-register.csv มีแถวของรายการอ้างอิงครบทั้ง 7 รายการ แถวแรกตรงกับหัวคอลัมน์ของแม่แบบ และไม่มีแถวใดเป็น fabricated / phantom ที่ search_sources มีแหล่งเดียว

ขั้นที่ 4 — ตรวจหนึ่งรายการกับฉบับเต็ม

เลือกรายการเสี่ยงหนึ่งรายการจาก citation-register.csv เปิดบทความนั้นใน ThaiJO ตรวจด้วยสี่คำถาม (เหมือนขั้นที่ 3 ของ workshop "ทะเบียนการอ้างอิงและคุณภาพของชุดอ้างอิง") แล้วแก้ checked_against, status, decision และใส่ชื่อของคุณใน reviewer

ตรวจ: แถวนั้นมี checked_against = full_text หน้าหรือส่วนของต้นฉบับใน support สถานะเป็นหนึ่งในหกสถานะ และชื่อคุณใน reviewer

ขั้นที่ 5 — จดสิ่งที่ AI จัดการได้

จดว่าปัญหาใด (ปี พ.ศ./ค.ศ., ชื่อผู้แต่ง, ชื่อเรื่องสองภาษา, ไม่มี DOI) ที่ AI จัดการถูก และที่คุณต้องแก้เอง

ตรวจ: บันทึกมีทั้งสี่ปัญหา แต่ละปัญหาระบุว่า "AI ถูก" หรือ "แก้เอง" พร้อมรายการที่เป็นตัวอย่าง

ขั้นที่ 6 — บันทึกรายการที่ต้องเปิดฉบับเต็มเอง

ชุดนี้ไม่ได้โหลดฉบับเต็มเข้าคลัง เครื่องมือส่งงานจึงต้องการบันทึกว่าฉบับเต็มของรายการใดต้องเปิดเองจากหน้าวารสาร วาง Prompt นี้

สร้าง module-04-work/thai-mock/output/manual-download.md ระบุรายการอ้างอิงทุกรายการใน refs.bib ที่ยังไม่มีฉบับเต็มในเครื่อง พร้อมแหล่งที่ต้องเปิดเอง (เช่น หน้าบทความใน ThaiJO) และรายการที่ฉันตรวจฉบับเต็มแล้วในขั้นที่ 4 ห้ามแก้ไฟล์อื่น

ตรวจ: manual-download.md มีรายการครบตาม refs.bib และรายการที่คุณตรวจในขั้นที่ 4 ถูกระบุว่าตรวจแล้ว

ขั้นที่ 7 — ส่งงาน

ให้ AI รันเครื่องมือ AIRR check → ยืนยัน → submit ของ Module 4 โดยระบุโฟลเดอร์งาน --file module-04-work/thai-mock

ตรวจ: check แสดง AIRR CHECK PASS · module-4 และก่อนยืนยัน submit แสดงจำนวนรายการอ้างอิง 7 รายการ และตรวจฉบับเต็มอย่างน้อย 1

Exploring

ตรวจรายการอ้างอิงภาษาไทย: ไม่พบใน OpenAlex ไม่ได้แปลว่าปลอม

ในโจทย์นี้คุณจะเขียน prompt เองทีละขั้นให้ AI สร้าง refs.bib คลังฉบับเต็ม และทะเบียนการอ้างอิงของงานนิสิตที่มีรายการภาษาไทยปน แล้วตรวจรายการภาษาไทยด้วยตนเอง

ไม่มี prompt สำเร็จรูปให้ ใช้ Prompt ของบทความจำลองเป็นโครงได้ แต่ต้องเขียนเองทีละขั้น

ก่อนเริ่ม (ต้องมีอยู่แล้ว)

  • ทำ workshop ของหัวข้อนี้กับบทความจำลองภาษาไทยแล้ว
  • course-materials/module-04/citation-audit-rules.md และ citation-register-template.csv (ตัวติดตั้ง Module 1 วางไว้ให้ อ่านอย่างเดียว)
  • OpenAlex API key ในตัวแปร OPENALEX_KEY และคลัง literature/ เดิม
  • บทหรือส่วนของวิทยานิพนธ์ที่มีการอ้างอิงมากและมีรายการภาษาไทยปนอยู่ เช่น บททบทวนวรรณกรรม (เฉพาะงานที่ได้รับอนุญาต และตัดข้อมูลส่วนบุคคลออกก่อน)

โจทย์

  1. สร้างโฟลเดอร์ module-04-work/<ชื่องาน>/input/original/ แล้ววางเอกสารลงไป
  2. สร้างไฟล์ module-04-work/<ชื่องาน>/output/prompts.md สำหรับเก็บ prompt ที่ใช้ทุกรอบ
  3. เขียน prompt เองทีละขั้น: สร้าง refs.bib → คลังฉบับเต็มและ manual-download.md → ทะเบียนการอ้างอิง
  4. ให้ความสำคัญกับรายการภาษาไทย: ทุกรายการที่ไม่พบใน OpenAlex ต้องค้นต่อในแหล่งไทยก่อนให้สถานะ
  5. ตรวจรายการภาษาไทยอย่างน้อย 2 รายการด้วยตนเองในแหล่งไทย และบันทึกการแปลงปีกับการเทียบชื่อผู้แต่ง

  • prompt ต้องมีครบเจ็ดองค์ประกอบ:

    แหล่งที่อนุญาต แหล่งใดก่อนหลัง สำหรับรายการภาษาอังกฤษและภาษาไทย
    วิธีจับคู่ ลำดับการจับคู่ ทั้งภาษาไทยและภาษาอังกฤษ
    การดาวน์โหลด ใช้ policy และคลังเดิมอย่างไร รายการที่ต้องดาวน์โหลดเองไปอยู่ที่ใด
    สิ่งที่ส่งมอบ ชื่อไฟล์ และแม่แบบ/กติกาที่ต้องใช้
    กติกาเมื่อไม่พบ ต้องบันทึกอะไร และห้ามทำอะไร
    จุดหยุดรอ หยุดตรงไหนเพื่อให้คุณตรวจ
