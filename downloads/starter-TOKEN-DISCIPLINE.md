# TOKEN DISCIPLINE — คุณภาพสูง แต่ใช้ AI ให้คุ้มค่า

## หลักเริ่มต้น

อย่าประหยัดจนงานแย่ แต่อย่าอ่าน อธิบาย หรือวนซ้ำเกินความจำเป็น Workspace นี้
ใช้ `T1 Standard` และ `C0 Economy` เป็นค่าเริ่มต้น

## Token Modes

| Mode | ใช้เมื่อ | พฤติกรรม |
|---|---|---|
| `T0 Quick` | wording, command หรือการตรวจจุดเดียว | ตอบสั้นและอ่านเฉพาะจุด |
| `T1 Standard` | งานทั่วไป | อ่านไฟล์ที่เกี่ยวข้อง ทำ spec/eval แบบย่อ และตรวจเฉพาะจุด |
| `T2 Deep` | งานวิจัย reviewer architecture หรือ policy เสี่ยง | วิเคราะห์ลึกโดยกำหนด scope และ review gate |
| `T3 Agentic Run` | แก้และทดสอบหลายรอบ | ทำเป็นรอบเล็ก จำกัด loop และรายงาน test/blocker |

## ประเมินก่อนงานหนัก

- `Low`: ใช้บริบทไม่กี่จุดและไม่มี test หนัก
- `Medium`: อ่านหรือแก้หลายไฟล์และมี smoke test
- `High`: scan กว้าง, ค้นเว็บหลายแหล่ง, อ่าน corpus ใหญ่, rewrite ทั้งชุด หรือ
  build/test หลายรอบ

สำหรับงาน `High` ให้เสนอ 3 ทางก่อน:

1. **Economy:** อ่านเฉพาะไฟล์หลักและเสนอแผน
2. **Standard:** แก้เฉพาะขอบเขตและทำ smoke test
3. **Deep:** วิเคราะห์หรือทดสอบกว้างเท่าที่จำเป็น

ถ้าผู้ใช้สั่งชัดว่า “ทำเลย”, “รันให้เลย” หรือ “เอาให้จบ” ให้ทำต่อด้วยขอบเขต
เล็กที่สุดที่ยังทำงานสำเร็จและปลอดภัย

## พฤติกรรมที่ต้องใช้

- เริ่มจาก `AGENTS.md`, `.ai/PROJECT_STATE.md` และไฟล์ที่เกี่ยวข้อง ไม่ scan
  ทั้ง project โดยอัตโนมัติ
- ใช้ `input/markdown/` ซ้ำเมื่อไฟล์ต้นฉบับไม่เปลี่ยน ไม่ถอดเอกสารเดิมใหม่ทุกครั้ง
- สำหรับ corpus ใหญ่ ให้ทำ inventory แล้วเลือกส่วนที่ตรงกับคำถามก่อน
- อ่านเฉพาะ error ที่เกี่ยวข้องหรือประมาณ 30–50 บรรทัดท้าย ไม่ส่ง log ทั้งไฟล์
- ไม่ paste บริบทหรือบทสนทนาเดิมซ้ำ ให้อัปเดต `.ai/PROJECT_STATE.md`
- หยุดการวนแก้ที่ไม่มีเกณฑ์ผ่าน/ไม่ผ่าน แล้วกำหนด eval ก่อนรอบถัดไป
- สรุปผลก่อน รายละเอียดหลัง และสรุป diff แทนการพิมพ์ไฟล์เต็ม

## Prompt Compaction

หลังงานที่มีสาระ ให้เก็บ state เพียง:

- objective ล่าสุด
- งานที่เสร็จและหลักฐาน
- blocker และ next action
- ไฟล์ที่แตะและคำสั่ง/test ที่รัน
- การตัดสินใจที่ยังเปิดอยู่

## Hard Rule

ห้ามลดคุณภาพด้วยการตัด evidence check, test, validation หรือ review gate
ให้ประหยัดจาก context ที่ไม่จำเป็น ไม่ใช่จากความคิดที่จำเป็น
